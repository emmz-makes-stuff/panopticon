# Section 3 done: tagging changes

**Project tags on the card:** `ChangeCard` gained an init property, `ProjectTags: IReadOnlyList<ProjectTagRef>` (by
`key_key`, then `value_key`), so every read path carries them.
- **Why now, not in §5:** `ChangeCards.Query()` includes `ProjectTags → Tag`, and that's the only card builder
  (`ToCard`). A tagging call has to return a card that shows its tags, and project tags look the same to every
  viewer, so they didn't need to wait. `PersonalTags`, which are per viewer, are still §5.1.
- **`ChangeCards.GetIncludingArchivedAsync(id)`:** returns `(Card, Archived)`. Tagging works on archived changes,
  where `GetAsync` returns null.

**One write path:** `src/Panopticon.Server/Changes/ChangeTagging.cs`, `ApplyAsync(db, changeId, projectId, taggerId?,
addIds, removeIds)`.
- **Locking:** in one transaction, the Project's row is taken `FOR SHARE` (tag writes hold it `FOR UPDATE`, so a tag
  can't be deleted mid-way), and the change's row `FOR UPDATE`.
- **The checks, under the locks:** the tagger's role (a null tagger is the bootstrap token, which may tag), then that
  every id is the Project's. It returns `Done`, `NotAllowed` or `UnknownTag`, and changes nothing unless it's `Done`.
- **A tag in both lists** ends up on the change (`remove.Except(add)`). The spec doesn't say; this is my call, and
  it's recorded in `ChangeTagsRequest`'s doc comment.

**The dashboard endpoint:** `POST /api/changes/{id}/tags` `{ add: [guid], remove: [guid] }`, in
`Changes/ChangeTagEndpoints.cs` (mapped in `ServerSetup` with `app.MapChangeTags()`).
- **Answers:** 404 for a change that isn't visible, 400 "Only a Project's changes have project tags.", 400 for an empty
  request, 403 for a viewer, 400 for an unknown or deleted tag, and 200 with the card.
- **Live:** an active change's card is republished through `broadcaster.Publish`. An archived one's isn't, so it can't
  reappear on dashboards.

**MCP:**
- **`list_projects`:** `ProjectSummary` gained `Tags` (`IReadOnlyList<string>?`, canonical text), with sequence
  equality, where null equals empty. `Describe()` adds a `  tags: a, b` line under each Project that has any.
- **`tag_change`:** `Changes/TagChangeTool.cs`, with `TagChangeArguments(Change, Add, Remove, Project, Repo)` and
  `TagChangeResult(ChangeId, Change, Code, Tags)` in `Panopticon.Contracts/TagChange.cs`. The tool name constant is
  `ContractsAssembly.TagChangeToolName`.
- **What `tag_change` checks:** it parses the tags, finds the Project and your role (a bootstrap token counts as
  owner), refuses a viewer by naming their role, then finds the change: the active one first, else the latest archived
  one. An unknown tag's error says "PAN has no tag "bugg", and tag_change can only use existing tags. Its tags are: …".
  Only then does it call `ChangeTagging`.
- **Wording fix:** the D1 empty-value error read `"key:": "key:" has no value…`, with the tag quoted twice. It's now
  `"key:": there's no value after the ':'. …`.
