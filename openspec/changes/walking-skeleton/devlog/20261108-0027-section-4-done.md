**4.1 Contracts** (`src/Panopticon.Contracts/ReportProgress.cs`):

- `RepoRef(Host, Owner, Name)`, `AgentRef(Client, Machine)`, and
  `ReportProgressArguments(Repo, Change, Agent, TasksMarkdown, Section?)`.
  - `.ToToolArguments()` builds the MCP argument dictionary from JsonElements through
    `ContractsJsonContext`, so it's AOT-safe and needs no reflection.
  - The wire names are in `ReportProgressArguments.Names`: `repo`, `change`, `agent`,
    `tasksMarkdown`, `section`.
- `ReportProgressResult(ChangeId, Overall, CurrentSection?)`, with `.Describe()` giving
  "Overall 7/20 · section 2 Core 2/5".
- `ContractsJsonContext` uses camelCase and omits nulls.
- **Decision:** the round-trip tests live in `tests/Panopticon.Cli.Tests/ContractsTests.cs`, because
  the CLI is the AOT consumer. There's no separate Contracts test project.

**4.2 Auth** (`Auth/BootstrapToken.cs`):

- `BootstrapTokenHandler` (scheme `BootstrapToken`, constant `SchemeName`, because `Scheme` hides a
  base member). It compares the SHA-256 of the presented and configured tokens with
  `FixedTimeEquals`, never logs the token, and returns `NoResult` without a header and `Fail` otherwise,
  so both give 401.
- `/mcp` has `.RequireAuthorization()`.
- Startup checks use **`ValidateOnStart`** for `Panopticon:BootstrapToken`, `Panopticon:S3:*`
  (`S3Options.Validate`) and `ConnectionStrings:Panopticon`. They throw `OptionsValidationException`
  naming the key.

**4.3 Tool and composition:**

- `ServerSetup.AddPanopticon()` / `MapPanopticon()` hold all service and endpoint wiring, and
  `Program.cs` just calls them.
- MCP: `AddMcpServer().WithHttpTransport(Stateless).WithTools<ReportProgressTool>()`, then
  `MapMcp("/mcp")`.
- `ReportProgressTool` (`Reporting/ReportProgressTool.cs`) returns a `CallToolResult` itself: text
  `Describe()` plus `StructuredContent` (`ReportProgressResult`).
  - Validation names every missing or blank field (`repo.host`, … `tasksMarkdown`) and trims them.
  - `TasksDocumentTooLargeException` becomes `McpException`, i.e. a tool error with the message.

**4.4 Broadcaster:**

- `Live/ChangeBroadcaster` is a singleton. It gives each subscriber a bounded channel of 64 that drops
  the oldest card when full. `Subscription` is `IDisposable`, which unsubscribes and completes the
  reader.
- After recording, the tool loads the card through `Dashboard/ChangeCards.GetAsync` and publishes it.
- **`ChangeCard`** (`Dashboard/ChangeCard.cs`) is the dashboard's card shape: ChangeId, Repo{Host,Owner,
  Name}, Change, Agents[{Client, Machine, LastReportedAt}] newest first, CurrentSection?{Number, Title,
  Progress{Done,Total}}, Overall{Done,Total}, LastReportedAt.
  - `ChangeCards.ListAsync` already returns all changes, most recent first. **§5.1 maps it to
    `GET /api/changes`, and §5.2 streams the same records as SSE.**
  - The web types in §7 must match this JSON (camelCase, ASP.NET defaults).

**Tests (65):**

- `Infrastructure/PanopticonFactory` is a `WebApplicationFactory<Program>` per test, with its own
  database and bucket. Settings go in via `UseSetting`, which the start-up validation sees.
  `CreateMcpClientAsync(token)` returns a real MCP client over `HttpClientTransport`, using the
  factory's `HttpClient`.
- `Mcp/ReportProgressEndpointTests` covers discoverability, missing/wrong/unconfigured token, a valid
  report, named missing fields, oversized input, trimming and publish-on-accept.
- There are also broadcaster unit tests and token `Matches` cases.

**Gotchas:**

- **MCP SDK 2.4:** a tool parameter **without a default value is required**. The SDK rejects the call
  with `ArgumentException … missing a value for the required parameter` *before* the tool runs, even
  for nullable types. Give argument parameters `= null` defaults and put DI services first. The SDK
  never validates arguments against the schema, so the tool must.
- `McpException` messages reach the client. Any other exception becomes a generic "An error occurred".
  Expected error-path tests log McpException stack traces, which is noise, not failure.
- EF can't project into `ValueTuple` (`Reading as ValueTuple … not supported`), so load entities in
  tests.
