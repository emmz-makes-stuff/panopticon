This replaces the `## Next` of `20261107-2342-stopped-sdk-10-0-403.md`. The SDK blocker is resolved.

**Decisions (Emmz's answers):**

- **SDK minimum raised to 10.0.403.** Emmz installed it with **dotnetup**, which puts the SDKs in
  `~/Library/Application Support/dotnetup/dotnet`.
  - `global.json` pins 10.0.403 (`latestFeature`).
  - The `docs/dependencies.md` dotnet row now says `>=10.0.403`, and the install command is
    `dotnetup install 10.0.4xx`.
  - The `make deps` regex accepts 10.0.403–10.0.499 and 10.0.5xx+, and rejects 10.0.400.
  - Design D18 and ADR-0002 are updated.
  - Reason: 10.0.400 bundles Microsoft.DotNet.ILCompiler 10.0.11 (NU1903, GHSA-p3jp-9v83-76w9).
- **MinIO replaced by SeaweedFS** for both compose and Testcontainers (D13, D17). MinIO no longer
  publishes images: `minio/minio` and `minio/mc` are gone from Docker Hub, and quay.io refuses
  access.
  - Bucket creation uses an **`amazon/aws-cli` init container** (`s3 mb`). The app never creates
    buckets, matching the pre-provisioned Railway Bucket.
  - Rejected: S3Proxy (transient by default), and having the app ensure the bucket in Development
    (dev/prod drift).
  - ADR-0003, dependencies.md and tasks 1.5/3.2 are updated.

**Other choices this section:**

- **Central package management**, using `Directory.Packages.props`. It currently pins only
  `xunit.v3.mtp-v2` 4.0.2. Add package versions in the sections that use them:
  - ModelContextProtocol / ModelContextProtocol.AspNetCore **2.4.0**;
  - Microsoft.Extensions.Hosting **10.0.14**.
  - Versions came from `dotnet package search … --exact-match` (unsandboxed).
- `tests/Directory.Build.props` gives every test project `xunit.v3.mtp-v2`, `OutputType Exe` and a
  global `using Xunit`. CA1707 (underscores) is off for `tests/**`.
- **TypeScript 6.0.3, not 7.0.2.** `typescript-eslint` 8.72.1 has a peer dependency of
  `typescript >=4.8.4 <6.1.0`. Move to TS 7 when typescript-eslint supports it.
- Web toolchain: vite 8.3.6, vitest 5.1.0 (happy-dom 21.0.4), eslint 10.14.0 (flat config, `@eslint/js`
  recommended + `tseslint.configs.strict`), prettier 3.9.10 (printWidth 100).
- The Vite dev proxy targets `http://localhost:5080` (override with `PANOPTICON_DEV_SERVER`), because
  macOS ControlCenter holds port 5000. **Use 5080 for the server in development** (section 5.3/8.2).
- `compose.yaml` pins:
  - `postgres:17.11-alpine`, with user/password/db all `panopticon` on port 5432;
  - `chrislusf/seaweedfs:4.50`, running `server -s3` on port 8333 with identities from
    `local/seaweedfs-s3.json`. Access key `panopticon-local`, secret `panopticon-local-secret`. Local
    only, and the file says so;
  - `amazon/aws-cli:2.39.6`, creating bucket `panopticon-documents`.
  - Checked: `docker compose up -d --wait` brought both services healthy, the init created the bucket,
    an authenticated put/get/rm round trip worked, and a wrong key gave `InvalidAccessKeyId`.
- The CLI help lists `mcp`, but the command isn't implemented yet. That's an intended stub that §6.3
  fills in. The server is a stub with only `/healthz`.

**Gotchas:**

- Run `make test`, `make gates`, `npm install`, `dotnet package search` and every `docker` command
  **unsandboxed**. The Docker socket, nuget.org and the npm cache are blocked in the sandbox.
- For sandboxed `npm view`, pass `--cache <scratchpad>/npm-cache` and allow `registry.npmjs.org`.
- `npm ci` prints an `fsevents` install-scripts warning. It's harmless (optional macOS package, ships
  prebuilt), so it's not approved.
- Compose services may still be running locally (`docker compose ps`). They're harmless, and
  `docker compose down` stops them.

**Gates:** `BUILD_EXIT:0` `TEST_EXIT:0` `FORMAT_EXIT:0` `AOT_EXIT:0` `WEB_INSTALL_EXIT:0`
`WEB_BUILD_EXIT:0` `WEB_TEST_EXIT:0` `WEB_FORMAT_EXIT:0` `WEB_LINT_EXIT:0` `VALIDATE_EXIT:0`
`GATES_EXIT:0`. The AOT binary `artifacts/cli/panopticon` is a 1.1 MB arm64 Mach-O, and `--help` runs.
