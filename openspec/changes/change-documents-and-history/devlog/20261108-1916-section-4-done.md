# Section 4 done: bridge sends the whole folder and notices archives

<!-- Section: 4 · Tasks: 4.1–4.4 · Base: 6efbc1f -->

What landed:
- **4.1:** `ChangeDocuments.ReadAsync(root, change)` returns a `ChangeFolder(Directory, Archive, Tasks, Documents)`.
  It replaces `ReadTasksAsync`, which is gone.
  - **Reading the folder:** recursive, skipping links (`ReparsePoint` or `LinkTarget`, files and folders alike).
    Only `.md`, `.yaml` and `.yml` files are read, in ordinal order, under `/` paths.
  - **Text:** strict UTF-8. A byte order mark is dropped by hand, because the strict encoding's own `Preamble` is
    empty.
  - **Size limits:** checked on `FileInfo.Length` before anything is read, then again on the decoded byte count.
    Errors end "Nothing was sent."
  - **`ProgressReporter`** sends `Documents` and `Archive`, and logs "archived as …" for an archived report.
- **Shared path rules (decision).** `DocumentLimits.PathProblem` now holds the rules in Contracts, and both the
  server (`DocumentChecks`) and the bridge use them. Before, the server refused any `:`, so a legal Unix file such
  as `notes:a.md` would have got the whole report refused. Only a drive prefix (`C:`) now counts as rooted, and
  there's a server test for a colon path.
  - **A changed test.** `BridgeTests.Server_tool_error_comes_back_as_a_tool_error` relied on the server refusing an
    oversized `tasks.md`, which the bridge now refuses first. It now uses `FakeMcpServer(…, toolError:)`.
- **4.2:** `FindArchive` picks the ordinal-greatest `archive/<YYYY-MM-DD>-<change>` folder, matching the name
  exactly and case-sensitively. An active folder wins over an archive. The not-found error names both paths.
  Archive dates match `[0-9]`, not `\d` (which accepts any Unicode digit), on the bridge and the server.
  `BridgeDocumentTests` checks the end-to-end path to `/api/history`.
- **4.3:**
  - **Registry.** `ReportedChanges` is a singleton. `ProgressReporter` records each active change's latest client
    name, plus the repo root from the first success, and forgets a change once it's reported archived.
  - **Watcher.** `ArchiveWatcher` is a `BackgroundService` that waits for the root. It then runs a
    non-recursive `FileSystemWatcher` (`DirectoryName`; Renamed, Deleted and Error) feeding a one-slot signal
    channel. Debounce: keep waiting 1 s while signals keep coming, then scan. It also scans once at start and
    rescans on `Error`.
  - **Scan.** For each registered change whose folder is gone and that has an archive, it calls
    `reporter.ReportAsync(client, change, null)`.
  - **Failures.** Everything is caught and logged, and the change stays registered.
  - **Tests and AOT.** `ArchiveWatcherTests` covers the three scenarios. `make aot` gives `AOT_EXIT:0` with no
    warnings.
- **4.4:** `docs/cli.md` gains "What the bridge sends" and "Archives", and the troubleshooting list has entries for
  the new errors.
