**What landed:**
- **3.1, the scope and refusals:** `ReportRecorder.ResolveScopeAsync`, `ReportRefusedException`, and the `project`

- **3.2, linking:** the D4 order in `FindOrAddChangeAsync`, with tests in `ReportScopeTests`:
  - linking mid-change (one change, three events, the earliest still the first report);
  - a teammate's personal change untouched;
  - an archived personal change not moved;
  - the Project already having the change (the personal one is retired with `ArchivedAt = receivedAt` and no folder,
    and `RetiredChangeId` is set).

  The live `Archived` event is checked at the MCP level, in
  `ApiTokenReportTests.Linking_when_the_Project_already_has_the_change_publishes_the_personal_ones_archive`.
- **3.3, `list_projects`:**
  - **Contracts:** `ListProjectsResult` / `ProjectSummary(Id, Name, Code, Role)` (ids as strings, like
    `ReportProgressResult.ChangeId`), with `Describe()`, in `Panopticon.Contracts/ListProjects.cs`. The tool name is
    `ContractsAssembly.ListProjectsToolName`.
  - **The tool:** `Panopticon.Server/Projects/ListProjectsTool.cs`, registered in `ServerSetup`. It's ordered by code.
    A member gets their memberships with roles, and the bootstrap token gets every Project as `viewer`.
  - **Tests:** `Mcp/ListProjectsToolTests` (4).

**Gotchas:**
- **No `ProjectMember.Project` navigation:** query from `db.Projects` through `p.Members` (`SelectMany`).
- **Only invited addresses can sign in:** `CreateSignedInClientAsync(Sam)` times out waiting for the sign-in email
  unless Sam was invited first. To set up "not her Project", create it as the default member, then change or delete
  the `ProjectMembers` rows in the database.
