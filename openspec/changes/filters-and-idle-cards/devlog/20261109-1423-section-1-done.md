# §1 done: quiet thresholds and member ids on cards

Base `d3e809b` (the proposal commit on `change/filters-and-idle-cards`).

## What landed

- **`ActivityOptions`:** in `src/Panopticon.Server/Dashboard/ActivityOptions.cs`, bound from `Panopticon:Activity`, with `IdleAfter` 30 min and `StaleAfter` 4 h by default.
  - Validation runs on start through `ActivityOptionsValidation` (an `IValidateOptions`), so the message can say which setting is wrong. An out-of-order pair names both keys and gives both values; a non-positive one names its key.
- **`GET /api/settings`:** `DashboardEndpoints.SettingsPath`, member-only. It returns `DashboardSettings { idleAfterSeconds, staleAfterSeconds }` in whole seconds.
- **`CardAgent.MemberId`:** a `Guid?`, the last positional member with a default, set in `ChangeCards.ToCard`. It reaches `/api/changes`, `change-updated` events and `/api/history` entries, since they all build on `ToCard`.
- **README:** a configuration-table row for both settings.
- **Tests:**
  - new: `Dashboard/ActivitySettingsTests` (defaults, set values, out of order, equal, non-positive, 401);
  - `memberId` assertions in `ApiTokenReportTests` (two members' ids; null for the bootstrap token), `DashboardEndpointTests` (the event) and `ChangeEndpointTests` (history);
  - new helper: `PanopticonFactory.MemberIdAsync(email)`.

## Notes for later

- **Deferred nit:** `DashboardSettings.From` truncates to whole seconds, so a sub-second threshold (say `00:00:00.5`) passes validation but is served as 0. It's harmless in practice, and I didn't add a "≥ 1 s" rule the spec doesn't ask for.
- **The web side hasn't changed yet:** `web/src/types.ts` `CardAgent` has no `memberId` until §3/§4.
