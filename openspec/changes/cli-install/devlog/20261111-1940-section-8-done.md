## What landed

- **8.1** `BinaryReplacer.IsCliBinary(path)` is true only for a file named `panopticon` or `panopticon.exe`
  (case-insensitive). `update` refuses anything else before it makes a request, so `dotnet …/panopticon.dll update`
  can't replace the `dotnet` host. The `.old` clean-up in `CliApp` now uses the same helper. The old check,
  `GetFileNameWithoutExtension == "panopticon"`, also accepted `panopticon.dll`.
- **8.2** `UpdateCommand` catches `OperationCanceledException`:
  - When the caller's token was cancelled (Ctrl+C), it prints "Update cancelled. Nothing was changed." and exits 130
    (`CancelledExitCode`, the same as `login`).
  - Otherwise (HttpClient's timeout, or the stall timeout), it says "stopped answering, so the update timed out".
  - Each body read has a stall timeout: a linked CTS with `CancelAfter`, set by a constructor parameter that defaults
    to 30 s (200 ms in the tests).
  - `CliApp.UntilCtrlCAsync` is now shared by `login` and `update`. Before this, `update` ran with
    `CancellationToken.None`. Because cancellation now arrives as an exception, the `finally` deletes the temp file.
- **8.3** The download is rejected up front when `Content-Length` disagrees with the manifest's `size`. It's stopped
  as soon as the bytes read pass `size`. An `IOException` from a body read (an `HttpIOException`) is reported as "The
  download … broke off". Errors writing the file still reach the outer "Can't replace" catch, which is accurate for an
  unwritable directory.
- **8.4** `ServerAddress.TryParseArguments(command, …)` replaces the two copies of `TryParse`. `UpdateCommand.TryDelete`
  is gone, in favour of `BinaryReplacer.DeleteQuietly`, which is now public. `--help` lists `--version, version`. For
  `FreePort`, there's **one** helper rather than one per project: `Panopticon.Cli.IntegrationTests` already uses
  `Panopticon.Server.Tests.Infrastructure`, so `Infrastructure/FreePort.cs` there replaces all three copies, including
  the older `FreeTcpPort` in `ContainerEndToEndTests`.

Tests: `UpdateCommandTests` gained cases for a host binary (four names), `IsCliBinary`, a lying `Content-Length`, an
oversized body (it asserts the read stopped early), a broken-off body, a header timeout, a stalled body, and Ctrl+C.
`A_short_download…` now serves a body without a length, since the `Content-Length` check would otherwise catch it
first. `TestBody` is a non-seekable stream for these cases.
