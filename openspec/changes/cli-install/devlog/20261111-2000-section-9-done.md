## What landed

- **9.1** `CliCatalogue.Load` catches `IOException` and `UnauthorizedAccessException` for each build, logs an Error
  ("Can't read the CLI build {Path}"), and leaves that build out. If none can be read, the catalogue is empty, so the
  server still starts. Tests use a file with mode 000; they're skipped on Windows and when running as root.
- **9.2** `/cli/<rid>/<file>` sends `Cache-Control: no-cache`, and `PhysicalFile` keeps its ETag and Last-Modified,
  so a revalidation is cheap. The endpoint test asserts the header.
- **9.3** `install.ps1` moves `panopticon.exe.old` back when moving the new `.exe` in fails, then exits through
  `Fail` with "The CLI that was there is still there." It has no automated test (there's no `pwsh`), so 7.3 covers it.
- **9.4** `ApiError` gains an optional `detail`, the Problem's `detail`, which `api.ts` now passes in. On a 404 the
  Tokens panel shows `failure.detail`, and falls back to the built-in text only when there's no detail. There are new
  tests for a custom detail and for a 404 with none. An older test faked a shortened detail; it now uses the server's
  real message.
