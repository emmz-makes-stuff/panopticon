## What landed

- **7.1** `ReposAsync` (`src/Panopticon.Server/Changes/ChangePages.Repos.cs`) runs three bounded queries, all from
  `VisibleTo(viewer)`, so there's no raw SQL and visibility has one definition. The queries are: active changes (no
  retired copies); the five newest archived per repo (no retired copies); and a grouped count of every visible archived
  change per repo, retired copies included, which is what History lists with `?repo=`. `moreArchived` became
  `historyCount`, and `latestActivityAt` is gone. The order is worked out on the server from the active and shown rows
  (the newest archive is always among those shown).
  - **Gotcha:** EF can't translate `GroupBy(repo).SelectMany(g => g.OrderBy…Take(5))` ("could not be translated").
    The shape that works is the distinct repo ids, then `SelectMany(id => archived.Where(c => c.RepoId == id).OrderBy…
    .Take(5))`. A throwaway `ToQueryString` probe (deleted) showed the SQL is `ROW_NUMBER() OVER(PARTITION BY
    c0.repo_id ORDER BY c0.archived_at DESC, c0.id DESC) … WHERE row <= 5`, with `VisibleTo`'s predicate inside.
  - `RepoEndpointTests`: eight archived plus one newer retired copy gives five shown and `historyCount` 9.
    `RetiredCopyTests` now expects `historyCount` 2.
- **7.2** "All N in History" shows when `historyCount` is more than the archived changes shown. `failureText` is in
  `web/src/api.ts`.
  - **Emmz's choice (2026-11-15):** use the shared `failureText` everywhere, not only the five files the task named.
    It also replaces the copies and inline versions in `projects.ts`, `members.ts`, `metrics.ts`, `signIn.ts` and
    `device.ts`. The task text says so.
  - **Emmz's choice (2026-11-15):** link whenever History lists more than the page shows, even under five. So one

  - `ServerClockCookieHandler`'s comment says it moves only `Expires`, and that `Max-Age` wins when both are set.
  - design.md D5 and web/DESIGN.md (Repos page) now say "All N in History".
