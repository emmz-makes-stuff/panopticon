**Built:**

- **`SessionState.WaitingOnVisit`** (wire name `waiting-on-visit`). `PresenceStore.WaitingState(kind)` maps each prompt
  kind to its waiting state.
- **`PromptDetail.Visit`** carries the URL, reason and action to members who may answer. Everyone else gets only
  `SessionPrompt(Kind: Visit)`: the existing `SessionView.For` redaction drops the whole detail, so no new redaction
  code was needed. `PromptSnapshot.Visit` gives the answer endpoint the URL.
- **The ask endpoint was unchanged.** `PromptLimits.Problem` already checks visits (§2). Release (away off, 8 hours, no
  `wait` for 90s) is kind-agnostic in `Settle`, and the tests confirm it for visits.
- **`POST /api/prompts/{id}/answer`** takes `{ visited, message? }` for a visit:
  - It refuses `answers` or `allow` on a visit, and `visited` on a question or permission prompt.
  - It refuses a note over `MaxVisitNoteLength` (1,000). Deny messages stay at 500.
  - The note is trimmed (blank becomes null) and goes to the session only. The row records kind `visit`, outcome
    `done`/`cant`, and the URL.
- **`AnswerEntry.Url`**: `For()` now hides both `Questions` and `Url` from anyone who couldn't have answered.
  `AnswerEntry.KindOf` replaces `ChangePages`' "not permission means question" mapping, and throws on an unknown kind.
