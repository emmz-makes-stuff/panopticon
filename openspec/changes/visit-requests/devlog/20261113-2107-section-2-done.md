  otherwise refuse them.

**Decision: the check constraint now says `outcome IS NOT NULL` before `outcome IN (…)`.**

- **The hole:** a CHECK passes on NULL, and `NULL IN (…)` is NULL. So a permission row with no outcome got past
  agent-interaction's constraint, and a visit row with no outcome would have too.
- **The fix:** both branches have the explicit check. A permission-row test now covers it.
- **Why fix it here:** this change rewrites that constraint anyway, and the fix is two words. It's out of this change's
  scope otherwise, so the commit body says so.
