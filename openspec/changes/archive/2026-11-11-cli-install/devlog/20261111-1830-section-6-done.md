## What landed

- **`cli-dist/`:** only `cli-dist/.keep` is tracked, and its text says what the folder is. `.gitignore` has
  `cli-dist/*` and `!cli-dist/.keep`. The Dockerfile's runtime stage runs `COPY cli-dist/ /app/cli/` after the app
  copy, so `/app/cli` is the catalogue's default directory. `.dockerignore` doesn't exclude `cli-dist`.
- **`make cli-dist-linux`:** a Native AOT publish in `mcr.microsoft.com/dotnet/sdk:10.0.404` for the Docker host's
  arch. It reads `docker version --format '{{.Server.Arch}}'`: `amd64` gives `linux-x64` and `arm64` gives
  `linux-arm64`. Two details in how it runs:
  - Only the CLI's and Contracts' sources go in, piped through `tar`, so the host's `obj/` folders are never
    touched. `COPYFILE_DISABLE=1` stops macOS `tar` adding AppleDouble `._*` files, which CSC rejected as binary
    files.
  - It mounts the stable `cli-dist/` folder and writes into `$rid/` there. An earlier version deleted and recreated
    `cli-dist/$rid` and mounted that, which failed once with "cannot create /out/panopticon", probably OrbStack
    holding the old folder.

  `CLI_DIST_VERSION` defaults to `0.0.0-dev` and is written to `cli-dist/version`. It prints `CLI_DIST_EXIT:<n>`.
- **`make e2e`** now depends on `aot cli-dist-linux`. `ContainerEndToEndTests` has a new step 0,
  `InstallOnCleanLinuxAsync`, and the server container gets the network alias `server`. The step:
  1. Gets `/api/cli` from the host, and checks for version `0.0.0-dev` and one Linux platform.
  2. In `buildpack-deps:bookworm-curl` (Debian 12, curl, glibc 2.36), runs `curl http://server:8080/install.sh`,
     pipes it through `sed` from `PublicUrl` to `http://server:8080`, then through `sh`.
  3. Checks the "Installed panopticon 0.0.0-dev to /root/.local/bin/panopticon" line, the login line, and
     `panopticon --version`.
  4. Checks that `panopticon update --server http://server:8080` is refused ("needs an https server"), which checks
     4.3 on real Linux.

  The `sed` is needed because `PublicUrl` is the host's `localhost:<port>`, which can't be reached from another
  container. Everything else runs as served. Building the image with builds and with only `.keep` both work: they
  were inspected with `find /app/cli`, and the bundled binary runs in the image.
- **`.github/scripts/stage-deploy-context.sh <dist> <version> <out>`:**
  - It runs `git archive HEAD` into `<out>`, installs every platform's build from `<dist>/cli-<rid>/` into
    `cli-dist/`, writes `version`, and removes the two `cli-dist` lines from the staged `.gitignore`.
  - It refuses a version that isn't a release version, a missing platform, and an `<out>` that isn't empty.
  - The dry run checked a full stage and the three refusals.
- **`.github/workflows/deploy.yml`** is renamed to "Release and deploy", with `defaults.run.shell: bash`:
  - **`cli`** is a `fail-fast` matrix on `ubuntu-22.04`, `ubuntu-22.04-arm`, `macos-15` and `windows-2025`. Each
    job:
    1. Sets up .NET from `global.json` (plus clang and zlib on Linux).
    2. Takes the version from the tag, and rejects anything that isn't `v<semver>`.
    3. Publishes with `-p:Version`.
    4. **Runs `--version` and compares it with the tag.**
    5. Uploads the `cli-<rid>` artefact.
  - **`release`** (`contents: write`) names the assets `panopticon-<rid>[.exe]`, writes `SHA256SUMS`, and runs
    `gh release create --verify-tag --generate-notes`.
  - **`deploy`** (needs both) stages the context, then runs `railway config apply` from the checkout, then
    `railway up "$RUNNER_TEMP/context" --path-as-root --service panopticon --ci`.
- **`install.sh`** has a `shellcheck disable=SC2016` on the `PATH` hint, which prints a literal `$PATH` on purpose.
