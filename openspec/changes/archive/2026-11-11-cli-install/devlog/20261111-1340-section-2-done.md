## What landed

- **The contract** (`src/Panopticon.Contracts/CliManifest.cs`):
  - `CliManifest(Version, InstallSh, InstallPs1, Platforms)` and `CliPlatformBuild(Url, Size, Sha256)`, registered
    in `ContractsJsonContext` for the CLI's AOT build.
  - `CliPlatforms`: the four RIDs, `All`, `ManifestPath` (`/api/cli`), and `FileName(platform)` (`panopticon.exe` for
    `win-*`).
- **The catalogue** (`src/Panopticon.Server/Distribution/CliCatalogue.cs`):
  - `CliDistributionOptions` holds `Panopticon:CliDirectory`, which defaults to `<AppContext.BaseDirectory>/cli`.
  - `CliCatalogue.Load` reads `version` (trimmed). The version must match `^[0-9A-Za-z][0-9A-Za-z.-]{0,63}$`, because
    it goes into URLs and, in §3, into the rendered `sh`/PowerShell.
  - It hashes each `<platform>/<file>` present with SHA-256 (lower-case hex).
  - It's empty when the version file is missing or invalid, or no build is present. It logs a warning saying why.
- **Registration:** the catalogue is a singleton, resolved eagerly in `MapPanopticon`, so it loads at start-up (D1).
- **The endpoints** (`Distribution/CliEndpoints.cs`, `MapCliDistribution`). Both are anonymous, and both are mapped
  before the fallback.
  - `GET /api/cli` builds its URLs with `SignInEndpoints.LinkRoot`: `PublicUrl`, or the request host in Development
    only.
  - `GET /cli/{platform}/{file}` is a `PhysicalFile` served as `application/octet-stream`, as an attachment. It's a
    plain-text 404 when the platform or file is unknown.
  - With an empty catalogue, the manifest is a Problem Details 404, and downloads are a plain-text 404.
    `CliCatalogue.NoBuildsMessage` names `make install`.
- **The tests:**
  - `tests/Panopticon.Server.Tests/Infrastructure/CliBuildsDirectory.cs` is a fake-builds dir helper, for §3's and §4's
    tests too.
  - `Distribution/CliCatalogueTests.cs` (8) and `Distribution/CliEndpointTests.cs` (15): the manifest values and
    hashes, `PublicUrl` vs a spoofed `Host`, each platform's bytes and headers, unknown and mismatched paths
    returning 404 rather than the app shell, a missing platform, the no-builds 404s, and `/healthz` still OK.

## Decisions

- **Partial catalogues are allowed.** One platform present is enough. The manifest lists only what's there, so §6's
  `make cli-dist-linux` (one Linux RID for `make e2e`) gives a working server. A release always has all four,
  because CI fails otherwise (D7). The spec's "Server without CLI builds" covers only the zero-build case.
- **Problem Details** for the `/api/cli` 404, not the design's `{ "error": … }`, to match the rest of the API.
  `design.md` D4 was updated to match.
