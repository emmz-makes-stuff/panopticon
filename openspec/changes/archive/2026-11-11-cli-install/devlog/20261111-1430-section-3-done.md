# §3 done: the install scripts

<!-- Section: 3 · Tasks: 3.1, 3.2 · Base: 84e9476 -->

## What landed

- **The templates** are `src/Panopticon.Server/Distribution/install.sh` and `install.ps1`. They're embedded
  resources (`LogicalName` `Panopticon.Server.Distribution.install.{sh,ps1}`), and line endings are normalised to LF
  when read.
- **`CliInstallScripts.RenderSh`/`RenderPs1`** fill in the placeholders:
  - `@@SERVER@@` (quoted), `@@SERVER_DISPLAY@@` (in comments) and `@@VERSION@@`.
  - `@@PLATFORM_CASES@@`: one `case` arm per non-Windows build, `<rid>) url='…'; sha256='…' ;;`.
  - `@@PLATFORM_LIST@@`.
  - `@@WIN_URL@@`/`@@WIN_SHA256@@`, which are empty when there's no Windows build, so the script fails with "this
    server has no Windows build".
  - Values are quoted with `ShQuote` (`'…'\''…'`) and `PsQuote` (`'…''…'`).
  - The server text is `PublicUrl` without its trailing slash, as typed in `panopticon login --server`.
- **The endpoints:** `GET /install.sh` and `GET /install.ps1` go through `CliEndpoints.InstallScript`. They serve
  `text/plain; charset=utf-8` with `Cache-Control: no-cache`, and an empty catalogue gives `NotFoundText(NoBuildsMessage)`.
- **`install.sh` behaviour**, in order:
  1. Works out the platform from `uname`. The test-only overrides are `PANOPTICON_UNAME_S`, `_M` and `PANOPTICON_LIBC`.
  2. Detects musl through `/lib/ld-musl-*` or `ldd --version`.
  3. Picks the platform, or fails as unsupported.
  4. Downloads to `$dir/.panopticon-install-$$` with curl or wget, checks the SHA-256 with sha256sum or shasum, then
     `chmod 755`.
  5. **Runs `--version` on the temp file before moving it**, so a machine with too old a glibc keeps its old CLI.
  6. Runs `mv -f`, prints the `PATH` hint, then `panopticon login --server <server>`.

  The traps remove the temp file.
- **`install.ps1` behaviour:**
  1. Runs as a `& { … }` block, so `irm | iex` stops on `throw`.
  2. Rejects non-x64, and ARM64 through `PROCESSOR_ARCHITECTURE`/`PROCESSOR_ARCHITEW6432`.
  3. Downloads with `Invoke-WebRequest`, checks with `Get-FileHash`, and runs `--version` on the temp `.exe`.
  4. Renames an existing `panopticon.exe` to `.old`, then moves the new one in.
  5. Adds `%LOCALAPPDATA%\Programs\panopticon` to the user `PATH` if it's missing, and prints the login line.

  §4 deletes the stale `.old` file at CLI start.
- **The tests:**
  - **`InstallShTests` (11)** run the rendered script under `/bin/sh` with a clean environment against Kestrel on a free
    port, with `PublicUrl` set to that address. The fake builds are `#!/bin/sh` echo scripts. They cover:
    - the default directory and the login line
    - the `PATH` hint
    - `PANOPTICON_INSTALL_DIR` replacing an old file
    - a checksum mismatch, by rewriting a build after start-up
    - a build that won't run
    - three unsupported platforms, and musl
    - the headers, and no leftover `@@`
  - **`CliEndpointTests`** add three tests: the `sh` script's URLs are all on `PublicUrl` despite a spoofed `Host`,
    the PowerShell script's server, URL and hash, and the PowerShell script with no Windows build. Two cases join the
    no-builds theory.

## Decisions

- **The version check runs before the move** (D3 had it after installing). That way a failed check keeps the old CLI,
  which the spec's "change nothing" needs.
- **`mkdir -p` happens before the download**, so a checksum failure on a fresh machine can leave an empty
  `~/.local/bin`. That's harmless, and no file is changed.
- **`install.ps1` has no automated run.** As planned, it's a hand check in §7.3.
