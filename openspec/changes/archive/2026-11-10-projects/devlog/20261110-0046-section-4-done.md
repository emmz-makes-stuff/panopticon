**What landed:**
- **4.1, `Projects/Viewer.cs`:**
  - **`Viewer`:** the member id plus a `ProjectIds` list. A list, so that EF can translate `Contains`. `LoadAsync`
    builds it, and the endpoint binding uses `static BindAsync(HttpContext)`, so any Member-policy endpoint can just
    take a `Viewer` parameter.
  - **`VisibleTo(viewer)`:** the D2 rule, on `IQueryable<Change>`.
  - **Where it's applied:**
    - `ChangeCards.ListAsync`;
    - `ChangePages`: `GetAsync`, `RenderAsync` (checks visibility before reading the document), `HistoryAsync` and
      `HistoryChoicesAsync`;
    - `MetricsReader`: `ForChangeAsync` and `ForTeamAsync`.
  - **Tests:** `Changes/VisibilityTests`, including the outsider sweep. Put any new change-reading endpoint into
    `To_an_outsider_another_Projects_changes_dont_exist_on_any_endpoint`.
- **4.2, the scoped stream:**
  - **`ChangeScope`:** it moved to `Projects/Viewer.cs` and gained `ChangeScope.Bootstrap`. `Viewer.CanSee(scope)` is
    the in-memory twin of `VisibleTo`.
  - **Events:** `ChangeEvent.Updated(Card, Scope)` and `Archived(ChangeId, Scope)`. `Publish` and `PublishArchived`
    require a scope.
  - **`RecordedReport.Scope`:** the change's scope after the report. A retired personal change's scope is
    `(null, reporter)`, built in `ReportProgressTool`.
  - **`StreamAsync(broadcaster, viewer, subscribed, keepAlive, recheck, ct)`:** `recheck` returns the reloaded
    `Viewer`, or null to end the stream. The endpoint does `IsLiveAsync`, then `Viewer.LoadAsync` with the request's
    db.
  - **Tests:** `Dashboard/ScopedStreamTests`, two `StreamAsync` tests and one HTTP test of removal mid-stream.
- **4.3, the Project in the read models:**
  - **Cards:** `ChangeCard` gains `CardProject? Project` and `bool Personal`, both trailing and optional. `Personal`
    is `OwnerMemberId != null`, so a bootstrap card has neither. `HistoryEntry` gains both, and `ChangePage` gets them
    through its card.
  - **The filter:** `HistoryFilter` gains `Project` and `Personal`. `TryParse` takes a `project` argument (an id, or
    `personal` in any case) and gives a 400 that says "project must be a Project id or personal".
  - **Choices:** `HistoryChoices` gains `Projects` (`CardProject`, by code) and `Personal`.
  - **Tests:** `Changes/ProjectFilterTests`.

**Choices of mine that the design doesn't spell out:**
- **`ChangeCards.GetAsync` isn't scoped,** although D2 lists it. Its only caller is the live publish, which has no
  viewer. The stream filters per subscriber instead (D3), and its doc comment says so.
- **A ping on a busy stream:** a stream busy with other scopes' events would send this viewer nothing and never go
  quiet. So it now also pings when nothing has been sent for a keep-alive.
- **`HistoryChoices.Personal`:** D9 names only `projects`, but the spec ("Project filter choices") offers "Personal"
  only when the viewer has a personal change. So there's a flag.
- **`ApiTokenReportTests.A_removed_members_agent_stays_on_the_card_with_their_name`:** Sam now reports into a shared
  `PAN`, because Sam's personal work is hidden from Emmz. It still removes Sam with `DELETE /api/members/{id}`, which §5
  rescopes.
