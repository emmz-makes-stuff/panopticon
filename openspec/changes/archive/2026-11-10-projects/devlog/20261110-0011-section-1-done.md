**What's settled before building.** These came from Emmz on 2026-11-09 and 2026-11-10. They're in
`docs/DISCOVERY.md` and the change's artifacts, but repeated here for a cold start.
- **Visibility:** unlinked work is visible only to its reporter.
- **The link:** `.panopticon.json` is committed in the repo.
- **Invites:** by email, which also grants sign-in.
- **Roles:** all three can report.
- **Creating:** anyone who can sign in can create a Project.
- **Codes:** fixed once created.
- **Owners:** several are allowed, but there must always be at least one.
- **The Members page:** it lists the people you share a Project with. Only initial members can remove someone from
  the server.
- **In the views:** the code and a Project filter.
- **Linking mid-change** moves your own personal change into the Project. This came from a side agent's note, and Emmz
  chose it. It's task 3.2.

**1.1, the entities.**
- **New:** `Project` (with `CodeKey` as the unique lower-case twin), `ProjectMember` (with a composite key and the
  `ck_project_members_role` check) and the `ProjectRoles` constants.
- **`Change`:** gains `ProjectId` (with a navigation) and `OwnerMemberId`, plus the `ck_changes_one_scope` check.
- **Identity indexes:** both are rebuilt with the two scope columns, with `AreNullsDistinct(false)`. The new names are
  `ix_changes_repo_id_name_key_project_id_owner_member_id` and `…_archive_folder_…`.
- **The migration:** `20261110000627_Projects`.

**1.2, the backfill and the down migration.**
- **Up:** sets `owner_member_id` from the member behind each change's earliest report that has one. Bootstrap or old
  rows stay both-null.
  - **Wording fix:** design D1 said "earliest report", which was slightly off, so I made it "earliest report that has
    a member" to match.
- **Down:** deletes the newer changes of any set that would collide under the old indexes, along with their dependants,
  before restoring the old indexes.

**Tests:** `MigrationTests` now has 18, five of them new:
- the scope uniqueness, with all-null scopes equal;
- the one-scope check;
- the code uniqueness and the role check;
- the backfill;
- the rollback.

**Not yet (by design):** `ReportRecorder` still creates every change with both scope columns null, which reads as
"visible to all". Its `FOR UPDATE` lookup ignores the scope too. That's fine until §3.1, because nothing sets a scope
yet. §3.1 must add the scope to that lookup.

**Self-review:** nothing found beyond the wording fix above. A stray `.tmp` file from a failed `awk` attempt was
deleted.

**Gates:** `BUILD_EXIT:0`, `AOT_EXIT:0`, `TEST_EXIT:0` (519 tests), `WEB_INSTALL_EXIT:0`, `WEB_BUILD_EXIT:0`,
`WEB_TEST_EXIT:0`, `WEB_FORMAT_EXIT:0`, `WEB_LINT_EXIT:0`, `VALIDATE_EXIT:0`. The first run had `FORMAT_EXIT:2`
