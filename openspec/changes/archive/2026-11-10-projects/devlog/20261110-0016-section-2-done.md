# Section 2 done: Projects and their members

<!-- Section: 2 · Tasks: 2.1–2.2 · Base: ee98ad3 -->

**The endpoints:** `src/Panopticon.Server/Projects/ProjectEndpoints.cs` (design D5), registered with
`app.MapProjects()`.
- **Projects:**
  - `GET /api/projects` lists my Projects, by code, with my role.
  - `POST /api/projects` takes `{name, code}`. It returns 201 with a `ProjectView`, or 409 with "The code PAN is taken.
    Choose another."
  - `GET /api/projects/{id}` returns the `ProjectDetails`: members with roles, owners first.
  - `PATCH /api/projects/{id}` takes `{name}`. Owners only, and the code is ignored.
- **Members:**
  - `POST …/members` takes `{email, role}`.
  - `PATCH …/members/{memberId}` takes `{role}`.
  - `DELETE …/members/{memberId}` removes, or leaves when it's yourself.
- **Status codes:** not a member is 404 "There's no such Project." A member who isn't an owner gets 403 "Only the
  Project's owners can do that." The last owner gets 409 "A Project needs an owner. Make someone else an owner first."
- **Locking:** every membership write locks the `projects` row with `FOR UPDATE`, and re-reads the caller's role
  under the lock. So two owners demoting each other at once give one 200 and one 403, and one owner is left. A test
  covers this.

**Helpers:**
- **`ProjectCodes`:** a generated regex, `Rule`, `Key`.
- **`ProjectNames`:** 1 to 100 characters, trimmed.
- **`MemberInvites.FindOrAddAsync`:** finds an active member, reactivates a removed one, or adds a new one.
  - **Who uses it:** the Project invite. The old `MemberEndpoints.InviteAsync` has its own copy, which §5.1 deletes
    with `POST /api/members`.
  - **The race:** a unique violation aborts the Postgres transaction, so it can't be retried there. When two invites
    add the same new address at once, the loser gets a 409, "…was just invited elsewhere. Try again."
- **`ClaimsPrincipal.GetRequiredMemberId()`** (in `Auth/Sessions.cs`): for session-only endpoints. It throws if
  there's no member, which the Member policy rules out.

**Gotcha:** EF can't translate an `OrderBy` after a `Select` into a record constructor. Order an anonymous projection
first, then select the record.

**Tests:** `tests/Panopticon.Server.Tests/Projects/ProjectEndpointTests.cs`, 24 including theory rows. They cover
every scenario in "Creating a Project", "Project codes", "Project names", "Projects list", "Inviting to a Project"
and "Changing roles and removing", plus the race.
