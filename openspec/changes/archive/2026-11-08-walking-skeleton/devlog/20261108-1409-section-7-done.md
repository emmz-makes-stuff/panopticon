**A second §5 bug, found in the real browser:** the page rendered nothing.

- `MapFallbackToFile("{*path:regex(^(?!api/|mcp).*$)}", …)` had dropped the `nonfile` constraint that the
  default fallback pattern carries. So `/assets/*.js` and `*.css` matched the fallback endpoint.
  `UseStaticFiles` stands aside when an endpoint is already selected, so the assets came back as
  `index.html` (`text/html`), and the browser refused the module script.
- **Fix:** `{*path:nonfile:regex(^(?!api/|mcp).*$)}` in `ServerSetup.cs`.
- New test `Built_assets_are_served_as_themselves_not_as_the_app_shell` covers a JS and a CSS asset with
  the right content types, and a missing asset as 404.
- The §5 test only checked `/`, a client route and `/api/*`. **Lesson:** a static-site check must fetch a
  real asset, not just the shell.
- Gotcha: perl `s|…|…|` with a `|` in the replacement mangles the line. Use Edit for code containing `|`.
