# §10 done: review fixes from the code review

<!-- Section: 10 · Tasks: 10.1–10.9 done · Base: 6e1b409 -->

All nine fixes Emmz agreed in `20261108-1428-review-fix-plan.md` are in. #9 (the double `/api/changes` fetch) was
left alone, as agreed.

- **10.1** `ReportRecorder` only moves a change's snapshot and `LastReportedAt` (and a change-agent's
  `LastReportedAt`) forward. Each attempt runs in a transaction that locks the change row with `FOR UPDATE`.
  Every report is still a `ReportEvent`. (See the handoff note `20261108-1433-…` for the details.)
- **10.2** `ServerForwarder` uses `await using` on the `HttpClientTransport`. The MCP client only disposes the
  session it connects, so the transport would leak when `McpClient.CreateAsync` threw.
- **10.3** IO and permission errors reading `tasks.md` become `Couldn't read '<path>': …`. A
  `JsonException` from the structured result, or a result missing `changeId`/`overall`/section members, becomes
  `… returned a malformed progress result: …`. Both are `BridgeException`s, so `ProgressReporter` logs them and the
  tool returns them as tool errors.
  - Tests through the real bridge: a `tasks.md` with mode 000 (skipped on Windows and for root), and a
    `FakeMcpServer` `HttpMessageHandler` that answers in plain JSON.
  - **Gotcha:** the current MCP SDK client sends **`server/discover` before `initialize`**. The fake has to answer
    unknown methods with JSON-RPC `-32601` (method not found) so the client falls back, not throw.
- **10.4** `/api/events` sends a named `ping` event (data `null`) after each quiet `Dashboard:KeepAlive`
  (a TimeSpan setting, default 25 s; it must be positive or start-up throws).
  - `StreamAsync` now yields `SseItem<ChangeCard?>`. It races the reader's pending `WaitToReadAsync` against the
    delay and carries the same wait over a ping, so no card is lost.
  - The dashboard only listens for `change-updated`, so it ignores pings. No web change was needed.
  - `PanopticonFactory` gained a `Settings` init property (extra `UseSetting`s).
  - Tests: a unit test (ping, then a published card still arrives) and an HTTP test whose first line is
    `event: ping`.
- **10.5** `TasksParser.InlineText` keeps `HtmlEntityInline.Transcoded` (`R&amp;D` → `R&D`, `&lt;b&gt;` → `<b>`,
  which the card shows as text).
- **10.6** `GitRepository.RunProcessAsync` (internal, split out of `RunGitAsync`) kills the process tree when
  `WaitForExitAsync` is cancelled. The test runs `sh -c 'echo $$ > pid; exec sleep 30'`, cancels, and checks the
  PID has exited.
- **10.7** The SPA fallback regex is now `^(?!(api|mcp)(/|$)).*$`.
  - `/api`, `/api/`, `/API/nothing` and `/mcp/nothing` don't get the shell.
  - `/mcp-setup`, `/apis` and `/changes/api` do.
- **10.8** `ProgressReporter` calls `RequireServer()` once and passes `endpoint, token` to
  `ServerForwarder.ForwardAsync`. The forwarder no longer takes `BridgeSettings`.
- **10.9** `SectionProgress` gained `IsNumbered`. `CurrentSection.Select` prefers an explicitly numbered match
  for the reported number. The `task-progress` delta spec's **Current section** requirement has the new sentence and
  an "Explicit number preferred" scenario. (The plan note said the Sections requirement, but Current section is
  where the choice is made.)
