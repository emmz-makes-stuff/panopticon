# Section 2 done: task progress parsing

<!-- Section: 2 · Tasks: 2.1–2.3 · Base: 7d3feb6 -->

The parser and current-section selector are in `src/Panopticon.Server/Progress/`, with Markdig
**1.6.0** and HTML disabled (design D8).

- **`TasksParser.Parse(string) → ParsedTasks`** returns `Sections` (Number, Title, Progress) and
  `Overall`.
  - It walks the top-level blocks. A level-2 heading starts a section, and checkbox list items at any
    depth (bullet or ordered, nested, inside quotes) count towards the current section and overall.
  - Tasks before the first section count only towards overall.
  - Over 1 MiB of UTF-8 throws `TasksDocumentTooLargeException`, whose message contains "1 MiB".
    The tool layer (§4.3) must map that to a tool error.
- **`CurrentSection.Select(parsed, reported)`** returns the reported section if it exists, else the
  first with unfinished tasks, else the last that has tasks, else `null` when no section has tasks.
- **`TaskProgress(Done, Total)`** is a record struct. `IsEmpty` (0 of 0) is the "empty" state that views
  must show, as opposed to 0%.

**Decision (a detail the spec left open): what counts as a checkbox.** It's a bracket pair at the very
start of the list item's paragraph, holding 0–3 non-bracket characters and followed by whitespace or the
end of the line. So `[ ]`, `[x]`, `[ x]`, `[~]`, `[-]` and `[]` are tasks, while `- [docs](url)`,
`- [TODO] …` and `- [x]nospace` are not. Done means the box holds only `x`/`X` after trimming. The
regex is `CheckboxPattern`, applied with `\G` at `paragraph.Span.Start`. Section titles come from inline
text (literal + code), so `` `web/` `` becomes `web/`, and HTML stays literal text such as
`<b>Bold</b>`. **Views must render titles as text** (§7: use `textContent`, never `innerHTML`).

**Gotcha:** the `_camelCase` naming rule (IDE1006, from `.editorconfig`) is **not** caught by
`make build`, only by `make format`. It applies to private **static** fields too, so use `_name`, not
`s_name`.
