# Section 5 done: dashboard read API and live stream

<!-- Section: 5 · Tasks: 5.1–5.3 · Base: 8f261db -->

**What landed:**

- **5.1 `GET /api/changes`** (`Dashboard/DashboardEndpoints.cs`, mapped by `MapDashboard()` from
  `ServerSetup.MapPanopticon`) returns `ChangeCards.ListAsync()` as camelCase JSON, most recent first.
  It's unauthenticated in this change.
  - JSON shape: `[{changeId, repo:{host,owner,name}, change, agents:[{client,machine,lastReportedAt}],
    currentSection:{number,title,progress:{done,total}}|null, overall:{done,total}, lastReportedAt}]`.
  - The web types in §7 must match it.
- **5.2 `GET /api/events`** is `TypedResults.ServerSentEvents` over `StreamAsync`. It subscribes to the
  broadcaster when the stream starts and disposes the subscription when the request ends (tested).
  - Each event is `event: change-updated`, with `id:` set to `lastReportedAt` in Unix ms and `data:`
    set to the card JSON.
  - **There's no heartbeat yet.** Railway or other proxies may close idle streams, and §7's
    `EventSource` reconnect plus full refresh covers that. Consider an SSE comment ping in a later
    change.
- **5.3 Static files and startup:**
  - `UseDefaultFiles` + `UseStaticFiles`, plus `MapFallbackToFile("{*path:regex(^(?!api/|mcp).*$)}",
    "index.html")`. Client routes get the shell, and unknown `/api/*` paths stay 404.
  - **`--migrate` applies migrations and exits.** It's stripped from `args` before
    `CreateBuilder`, because the command-line config provider rejects a bare switch. This is meant as
    a pre-deploy step.
  - In Development, migrations run at startup.
  - `appsettings.Development.json` holds the compose values (public and local-only, and says so),
    bootstrap token `dev-bootstrap-token`, and `Urls`.
- **Tests (70):** `Dashboard/DashboardEndpointTests` covers two changes in two repos (order and JSON
  shape), an empty list, an SSE event after a report, unsubscribing when the stream ends, and the shell
  at `/` and client routes but 404 for `/api/…`. `PanopticonFactory` gained `WebRoot` (init) for
  `UseWebRoot`, because `make gates` runs the .NET tests **before** the web build.

**Decision: the dev port is 7480, not 5080.**

- During the 5.3 check, 5080 was held by another of Emmz's projects (`Nova.GraphQL.Api`), so I didn't
  touch it. 5180 and 5280 were busy too.
- `appsettings.Development.json` `Urls` and the `web/vite.config.ts` proxy default now use
  `http://localhost:7480`. **This supersedes the §1 note's "use 5080".**

**Real-run check (5.3):**

- `docker compose up -d --wait`, `make web-build`, then
  `ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/Panopticon.Server -c Release
  --no-launch-profile`, all unsandboxed. The server reached "Now listening on http://localhost:7480"
  and the initial migration applied.
- Results: `/` 200 text/html (the Vite build), `/healthz` 200, `/api/changes` 200 `[]`,
  `/api/nope` 404, `/mcp` with no token 401.
- `--migrate` printed "No migrations were applied", exited, and never listened.
- The server was stopped afterwards, only after checking the PID was ours. **Nothing is running in the
  background.** The compose services may still be up, which is harmless.

**Gotchas:**

- The first EF migration run logs `fail: … Failed executing DbCommand … __EFMigrationsHistory`. That's
  EF probing a missing history table, and it's normal.
- `curl`/`wget` are blocked by a hook. For quick HTTP checks, use context-mode `ctx_execute` with JS
  `fetch`.
- To wait for the server, use a background `until grep -q 'Now listening|Unhandled' log` loop. Kill
  only PIDs whose command is `Panopticon.Server`.
- zsh has no `PIPESTATUS` (it's `pipestatus`).
