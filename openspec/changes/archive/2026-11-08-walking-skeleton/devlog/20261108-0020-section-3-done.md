**Decisions (Emmz's answer):**

- **`dotnet-ef` is a global tool**, not a local manifest. It was already installed at 10.0.11 and is now
  updated to **10.0.14**. Its row is in `docs/dependencies.md`, and `make deps` checks
  `dotnet ef --version | grep '^10\.'`.

**What landed:**

- **3.1 Model and migration.** `src/Panopticon.Server/Data/` holds `Entities.cs`, `PanopticonDb` and
  `Migrations/…_Initial`.
  - The model is snake_case through **EFCore.NamingConventions 10.0.1**
    (`UseSnakeCaseNamingConvention()`). It's set in `DbOptions.Configure`; use it everywhere a context
    is built.
  - Ids are `Guid.CreateVersion7()`. `ProgressSnapshot` is an owned type stored as `jsonb`
    (`OwnsOne(...).ToJson()`).
  - Unique indexes on the lower-cased `*_key` columns. Display values keep the casing first reported.
  - `DesignTimeDbFactory` lets `dotnet ef` run without a database. Regenerate the migration with
    `dotnet ef migrations add <Name> --project src/Panopticon.Server --output-dir Data/Migrations`
    (unsandboxed).
  - Migrations are `generated_code = true` in `.editorconfig`.
- **Versions:**
  - `Npgsql.EntityFrameworkCore.PostgreSQL` **10.0.3** depends on EF Core **10.0.4**, while `.Design`
    is 10.0.14, which gave **MSB3277**. Fixed with `CentralPackageTransitivePinningEnabled` and EF Core,
    Abstractions and Relational pinned to **10.0.14** in `Directory.Packages.props`.
  - AWSSDK.S3 **4.0.104.11**, Testcontainers / .PostgreSql **4.16.0**, Mvc.Testing **10.0.14** (for §4).
- **3.2 `S3DocumentStore`** (`Documents/DocumentStore.cs`):
  - It writes `documents/sha256/<hex>` if absent (HEAD, then PUT; a race is harmless).
  - `S3Options` (section `Panopticon:S3`: ServiceUrl, Region, AccessKey, SecretKey, Bucket,
    ForcePathStyle) has `Validate()`, which names the missing keys. **Call it at startup in §4**, so a
    misconfigured server fails fast.
- **3.3 `ReportRecorder`** (`Reporting/ReportRecorder.cs`) takes `ReportInput(RepoIdentity, ChangeName,
  AgentIdentity, ReportedSection, TasksMarkdown)` and returns `RecordedReport(ChangeId, Snapshot,
  ReceivedAt)`.
  - It parses first, so oversized input records nothing. Then it stores the doc, then does the upserts
    plus the event in one `SaveChanges`. It retries up to 3 times on Postgres unique violations
    (concurrent first reports).
  - It takes a `TimeProvider`.
- **Tests:**
  - `Infrastructure/PostgresFixture` and `S3Fixture` are assembly fixtures, with one container each.
    Each test gets its own migrated database and its own bucket. `ManualClock` is the test clock.
  - Covered: every Change identity, Agents on a change and Document retention scenario, plus
    oversized→nothing recorded, and 4 concurrent first reports→one change.

**Gotchas:**

- **SeaweedFS `-volume.max` defaults to 8.** Each bucket is a collection that claims volumes, so after a
  few test buckets `PutObject` fails with "We encountered an internal error". The fixture and compose
  now pass `-volume.max=0` (sized from free disk) plus a small `-master.volumeSizeLimitMB`.
- `.editorconfig` naming: **constants are PascalCase** (a new, more specific rule). Every other private
  field, `static readonly` included, is `_camelCase`. `make build` doesn't enforce IDE1006, only
  `make format` does.
- BSD `sed` has no `\b`, so use explicit patterns for renames.
- CA1859 fires in tests if a private member is typed as an interface but only ever holds one concrete
  type.

**Carry into §4:**

- `ReportRecorder` trusts its input. The tool layer must reject blank or whitespace repo, change and
  agent fields, and **trim** them before building `ReportInput`.
- Map `TasksDocumentTooLargeException` to a tool error stating the limit.
