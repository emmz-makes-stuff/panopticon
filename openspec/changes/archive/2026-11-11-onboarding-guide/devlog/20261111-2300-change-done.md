## Review

Checked against `specs/` (machine-setup, cli-distribution, projects), `design.md` D1–D9 and the ADRs.

- **No `installCli` leftovers.** `installCli.ts` is gone. The name survives only in the plan (`proposal.md`,
  `design.md` D1, `tasks.md` 2.1), which is history.
- **The `.install-cli-*` / `.setup-*` CSS split is deliberate** (§1 plan, §2 note). The install step keeps the old
  panel's markup so that its tests and CSS carry over, and `.install-cli-command` / `.setup-command` share their
  rules. That's a naming wart, not a defect, so it stays as it is.
- **Scenario coverage:** every machine-setup, cli-distribution and projects scenario has a named test
  (`setupGuide.test.ts`, `projects.test.ts`, `tokens.test.ts`, `CliEndpointTests.cs`), with one exception:
  - **Gap:** machine-setup "Hidden" has a second clause, *"and still shows on the Tokens page"*, that no test covers.
    It holds by construction, because `tokens.ts` never reads `SETUP_GUIDE_HIDDEN_KEY`, but a later change could
    break it unnoticed. Proposed fix: one `tokens.test.ts` case that sets the key in `local` and expects
    `.setup-guide` to show.
- **Errors:** none swallowed. `loadGuide` drops the guide when `/api/tokens` fails, on purpose (the comment says why,
  and a test covers it). A manifest failure shows a 404 detail or a reload hint, and the log-in step falls back to
  the page origin (D2).
- **A small duplication:** the install step's Copy handler repeats `copyable()`'s copy/status logic, because its text
  changes with the OS choice. It isn't worth abstracting.
