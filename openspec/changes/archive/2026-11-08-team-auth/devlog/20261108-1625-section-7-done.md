## What landed

- **7.1** `src/Panopticon.Cli/Config/CliConfigFile.cs` contains `SavedLogin {serverUrl, token}` and
  `CliJsonContext` (source-generated, indented).
  - `CliConfigFile.DefaultPath(env, isWindows, home)` follows D14 and ignores a relative `XDG_CONFIG_HOME`, as XDG
    says to.
  - `Write` is atomic: it writes a temp file in the same directory, created with `UnixCreateMode` 0600, then moves
    it over the old file. It creates the directory as 0700 and also `SetUnixFileMode`s it, because umask can
    loosen the create mode.
  - `Read` returns null for a missing or unreadable file. An unreadable file logs one stderr line with the path
    only. A JSON error is reported without the parser's message, which can quote the token.
  - `BridgeSettings.Resolve(env, config, stderr, cwd, machine)` takes each value from its variable, then the
    file. A blank value counts as unset, and the file is read only if a value is missing.
    `FromEnvironment(stderr)` wraps it.
- **7.2** New wording:
  - Missing config: "The bridge isn't configured: X is/are not set. Run 'panopticon login' on this machine, or set
    it/them in the agent's MCP server environment."
  - 401/403: "…rejected the token (401). Run 'panopticon login' to get a new token."
- **7.3** `src/Panopticon.Cli/Login/LoginCommand.cs`, wired into `CliApp`. Ctrl+C goes through
  `Console.CancelKeyPress`, which cancels a token, giving exit 130.
  - The server comes from `--server`, then `PANOPTICON_SERVER_URL`, then the saved login. With none, it's exit 1
    saying to pass `--server`.
  - The POSTs send `X-Panopticon-Request: 1`: the D6 middleware wants it on every non-GET `/api` call, open ones
    included.
  - It prints the URL and code, then polls after each `delay(interval)`. `slow_down` doubles the interval.
  - On `approved` it saves the base URL (with a trailing slash) and the token, and prints "Logged in to … as Name
    (email). Saved to <path>."
  - It's exit 1 on `denied`, `expired`, an HTTP error, or a non-Panopticon answer (a `JsonException`).
  - Everything it touches is injected (`Func<HttpClient>`, env lookup, `CliConfigFile`, machine name,
    `Func<TimeSpan, CancellationToken, Task> delay`, stdout, stderr).
  - **Test trick:** `LoginTests` injects a delay that advances the test server's `ManualClock`. Polling and the real
    10-minute expiry then run instantly, with no shortened lifetime needed. The first delay also approves or denies
    the printed code through a signed-in browser client.
  - The "Saved for the bridge" test reports through `BridgeHarness` using
    `BridgeSettings.Resolve(_ => null, config, …)`, and sees the member on the card.
- **7.4** `--help` lists `login [--server <url>]` and prints the saved-login path.
  - `PublishedCliTests` gained `Published_binary_help_lists_login` and
    `Published_binary_login_against_an_unreachable_server_fails_cleanly`.
  - `make aot` already runs with `-warnaserror`, so a trimming or AOT warning fails `AOT_EXIT`.
  - `docs/cli.md` gained "Log in", a rewritten "Configuration" (file, modes, precedence), a `.mcp.json` with no
    env, the Development bootstrap shortcut, and troubleshooting entries.
- **Test isolation fix:** the published binary now reads the user's real config file when a variable is unset.
  `PublishedCliTests` sets `XDG_CONFIG_HOME` and `APPDATA` to a temp directory for every child process. Any new
  test that runs the binary must do the same.
