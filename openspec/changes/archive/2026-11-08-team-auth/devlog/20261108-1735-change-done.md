## Findings, for Emmz to decide (none fixed yet)

1. **The bridge can send a saved token to a different server.** `BridgeSettings.Resolve` resolves the server URL and
   the token separately. With `PANOPTICON_SERVER_URL=https://a` in the agent's env and a saved login for `https://b`,
   b's token goes to a. The cli-bridge spec asks for this per-variable fallback ("When a variable is unset, it SHALL
   use the value saved"), so changing it is a spec change. One option: use the saved token only when its server
   matches the server in use.
2. **The cli-bridge "Token rejected" scenario reads stale.** It says the error tells you to run `panopticon login`.
   That's still true word for word, but since §9 the env-token error says to correct or remove `PANOPTICON_TOKEN`. The
   scenario could say that the error names the token's source and the fix for it.
3. **Nit:** in `web/src/router.ts`, two doc comments are stacked above `Teardown`. The first is left over.
4. **Nit:** in `web/src/views/signIn.ts` `confirmView`, any non-400 failure shows "Couldn't reach the server". That
   includes a 429 or 500 `ApiError`, where the server did answer. It should show `failure.message` for an `ApiError`.
