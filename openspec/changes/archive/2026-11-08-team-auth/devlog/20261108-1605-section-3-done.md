## What landed

- **3.1** `/api/changes` and `/api/events` need `AuthPolicies.Member`.
  - Unauthenticated calls get a 401 with no redirect: the Session scheme's default challenge is a plain 401.
  - `DashboardEndpointTests` sign in with `factory.CreateSignedInClientAsync()`.
  - New tests:
    - not signed in gets a 401 and no change data, on both paths;
    - a stale cookie gets a 401;
    - `/healthz`, sign-in and confirm stay open.
  - The app-shell tests were already unauthenticated, through `WebRootFactory` under Testing, and still pass, so
    the shell stays open.
- **3.2** `DashboardEndpoints.StreamAsync` takes `Func<CancellationToken, Task<bool>>? stillAllowed`.
  - The endpoint passes `sessions.IsLiveAsync(sessionId)`, using the request-scoped `SessionStore`.
  - The stream calls it before each ping and, on a busy stream, before sending once a keep-alive interval has
    passed (timed with a `Stopwatch`). On `false` it `yield break`s, so the response ends. The browser's
    reconnect then gets a 401, which 8.1 must turn into the sign-in page.
  - The test (`An_open_stream_ends_when_its_session_does`, covering sign-out and removal) uses a 100 ms
    keep-alive.
- **Breaking, until §8:** a local run's dashboard can't load data until the web sign-in pages exist. That's
  expected, and noted in the proposal summary.
