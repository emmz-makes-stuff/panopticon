## What landed

- **6.1** `Auth/ApiTokenHandler.cs` (scheme `ApiToken`) replaces `BootstrapTokenHandler` as the `Reporter`
  policy's scheme.
  - It looks up `api_tokens` by SHA-256 hash and needs the token unrevoked with an active member. Otherwise it's a
    401, and the token is never echoed.
  - It writes `last_used_at` with a conditional `ExecuteUpdate`, at most once a minute (`TouchInterval`).
  - Claims: the member id, `panopticon:token` (the token id), and the name.
  - The bootstrap token is accepted only when `IHostEnvironment.IsDevelopment()`, giving a principal with no member
    id. `BootstrapToken.cs` now holds only the options and `BootstrapToken.Matches`, the constant-time compare.
- **D16, confirmed:** MCP SDK 2.4.0 binds `RequestContext<CallToolRequestParams>` into tool methods, and its `User`
  is the request's authenticated principal. `IHttpContextAccessor` isn't needed.
  - `ReportProgressTool` takes `RequestContext<CallToolRequestParams> context` and sets
    `AgentIdentity.MemberId = context.User?.GetMemberId()`.
  - It doesn't appear in the tool's input schema (the schema test still passes).
  - The proof is `ApiTokenReportTests.Two_members_on_one_machine_…`: two tokens give two agents, each named.
- **6.2** `AgentIdentity` gains `Guid? MemberId = null`, and `FindOrAddAgentAsync` matches on
  `(member, client key, machine key)`. That matches the `NULLS NOT DISTINCT` unique index from §1.
  - `CardAgent` gains `string? Member`, the display name, null for no member. `ChangeCards` includes
    `Agent.Member`.
  - A removed member's agent keeps their name, because the row stays.
  - A rename shows at the next load, with no broadcast (D16).
- **6.3** `PanopticonFactory` now defaults to `Environment = "Testing"` and `bootstrapToken = null`.
  - `CreateMcpClientAsync(ct)` reports with the default member's real API token, from `MemberTokenAsync`, issued
    once per factory and cached under a lock.
  - `CreateMcpClientAsync(string? token, ct)` sends an explicit token or none.
  - New helpers:
    - `CreateApiTokenAsync(email, machineName)` runs a real start, approve and poll.
    - `SeedApiTokenAsync(email, machineName)` writes the row directly, for Kestrel-hosted servers
      (`PublishedCliTests`), where the in-memory https browser client can't reach Kestrel.
  - The bridge tests against a real server use `server.MemberTokenAsync(Ct)`. The fake and unreachable-server
    ones keep `PanopticonFactory.Token` as a dummy.
  - The successful bridge report now also checks the card's agent member (`"member"`).
  - The bootstrap tests (`Bootstrap_token_outside_development_…` and the Development acceptance test in
    `ApiTokenReportTests`) pass the token explicitly.
- Tests: `Mcp/ApiTokenReportTests.cs` (9). Server suite 215. `make test` green.
