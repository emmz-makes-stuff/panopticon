**2.1: `Metrics/SectionTimes`** (pure).
- **`Compute(events)`:**
  - It skips events that are pending or unreadable (`IsReadable`: `OverallTotal >= 0` and `Sections` not null).
  - It orders events by `ReceivedAt`, then `Id`.
  - **Decision:** it measures only the numbered sections in the *latest readable* report that have tasks there. A
    section that has since been removed drops out. Each section keeps its latest title.
  - **Start:** the first event where `done > 0` or `CurrentSection == number`.
  - **Finish:** the start of the final complete run. A report that lacks the section breaks the run.
- **`ToArchive(first, archivedAt, now)`:** the time to archive, or the time so far.

**2.2 / 2.3: `Metrics/MetricsReader` + `Metrics/MetricsEndpoints`** (scoped reader, `app.MapMetrics()`).
- **`ForChangeAsync`:**
  - `firstReportedAt` is the min `ReceivedAt` over *all* events, unreadable ones included. The spec says "first
    accepted report".
  - **Bug found in self-review and fixed:** an archived change uses `ArchivedAt` as "now". Without that, a section
    left unfinished at the archive kept growing. It has its own test.
- **`ForTeamAsync(HistoryFilter)`:** one query for the changes and one for their events (a subquery on the same
  filtered `IQueryable`).
  - **Decision: the figures cover *all* matching archived changes.** Only the weekly chart is limited to the last 12
    weeks. That's how I read the spec ("a weekly chart … over the last 12 weeks") together with D4.
  - **Decision: the section medians and the slowest list use finished sections only.** A section left unfinished at
    the archive has no real time.
  - **Median:** the mean of the two middle values, rounded down.
  - **Weeks:** `WeekStart` is Monday 00:00 UTC, and there are 12 buckets ending with the current week, oldest first.
  - **The slowest list:** the 10 slowest sections, ties ordered by change name then number. Each carries its
    `changeId`, `change` and `repo` (a `CardRepo`), so the web can link it.
- **Shapes:** as D4 says, with seconds as `long`. A median is null when there's nothing to take it over.

**Tests:**
- `SectionTimesTests` (13): every spec scenario, plus walking in received order, the latest title, and unknown
  progress skipped.
- `MetricsReaderTests` (9): `Median` and `WeekStart` at their boundaries.
- `MetricsEndpointTests` (10):
  - archived and active changes, the stop-at-archive case, a 404, and a 401 on both endpoints;
  - the team metrics, seeded over a Monday boundary so two week buckets are filled;
  - a repo filter, matched case-insensitively;
  - a filter matching nothing, which gives 0, null medians and 12 empty weeks;
  - an unreadable event skipped, so the section finishes at the archived report;
  - a 400 for `repo=panopticon`.
