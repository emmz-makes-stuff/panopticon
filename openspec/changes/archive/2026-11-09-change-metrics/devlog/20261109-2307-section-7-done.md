`/code-review` (medium) gave 10 findings. Emmz agreed three of them as §7. The other seven were declined, with
these reasons:
- **Partial metrics while the backfill runs:** design D3 says so outright.
- **Perf, loading every event (×2):** a known risk in design.md, which says history is small in v1.
- **The count leaves out changes with no events:** every change is created by a report, so an archived one always

- **The `-1` marker:** what D3 chose.
- **`MarkUnreadable`'s extra clears:** harmless.
- **A rolling deploy's old instance writing rows after the backfill:** a short window, and the next restart fills
  them. Parked.

**7.1, the backfill no longer sticks on one bad object.**
- **The bug:** any read error used to stop the run. One `tasks.md` that always fails (a 403, say) stopped every start
  at the same report, which broke the spec's "not fail the rest".
- **Now:** a read error skips that report with a warning, and its hash isn't tried again that run. Skipped reports
  stay pending, so the next start retries them. `MaxFailuresInARow` (3) errors in a row mean the store is down, and
  the run stops, saving what it filled.
- **API and log:** `BackfillResult` gains `Skipped`, and the finished log reads "filled N reports, M unreadable, K
  skipped".
- **Docs:** a new spec scenario, "A tasks.md that fails to read", plus updates to design D3 and the README.
- **Tests:** a skipped object (read once, the rest filled, the next run fills it), and an outage stopping the run.

**7.2, "unfinished" on archived changes.**
- **The rule:** a section that never finished, on an archived change, reads "unfinished, 2h", with no "so far". The
  row class is `unfinished`, styled like `in-progress`, and its rule is still dashed.
- **Where it's decided:** in `metricsPanel.ts`, from `metrics.active`. There's no server change: an archived
  change's clock already stops at `ArchivedAt` (§2).
- **Spec:** a new requirement, "Sections unfinished at archive". It's on its own because adding it to "Time per
  section" pushed that requirement over `openspec validate`'s 500-character limit (`VALIDATE_EXIT:1` the first time).
- **Also updated:** `DESIGN.md`, the README, and a test in `views/change.test.ts`.

**7.3:** `calendarDate(iso, { year: false })` now backs `weekLabel`, and has its first test.
