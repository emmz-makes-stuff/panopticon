# §4 done: the filter model and the dashboard's filters

Base `64aa019`.

## What landed

- **`web/src/filters.ts`**, the model for both pages:
  - **Parsing:** `parseFilters(params)` returns `{ filters, dropped }`.
    - `repo` and `owner` are parsed as the server does.
    - `member` must look like a GUID, and is lower-cased.
    - `status` must be one of active, idle or stale.
    - Blank values and unknown keys are ignored. Malformed keys go in `dropped`.
  - **Writing:** `toQuery(filters, keys = FILTER_KEYS)` writes the keys in the fixed order through `URLSearchParams`, so '/' becomes `%2F`. It writes only `keys`, so the history can leave out `status`.
  - **Matching:** `matches(change, filters, state?)` takes any `{repo, agents}`, so a history entry works too. The comparison ignores case, the person filter matches on `memberId`, and `status` is skipped when no state is given.
  - **Choices:** `filterChoices(cards)` has the same shape as the server's `HistoryChoices`. A member is named as on their newest card, and an agent with no member adds no person.
  - **The bar's options:** `filterOptions(choices, filters)` builds them, keeping a chosen value no change has as a "… (no changes)" option ("Unknown member (no changes)" for a person).
- **`web/src/filterBar.ts`:** `createFilterBar({ keys, onChange })` builds a `form.filter-bar`.
  - **Selects:** a labelled `select[name=<key>]` per key. The labels are Repo, Owner, Person, Machine, Agent type and Status, each with an "All …"/"Everyone"/"Any status" first option.
  - **The rest:** `.filter-clear` ("Clear filters", hidden when no filter is set) and `.filter-note`, which names the dropped keys.
  - **`update()`:** it rebuilds a select's options only when they've changed, so a live update doesn't close an open select.
- **`app.ts`:**
  - **Inputs:** `AppDeps.filters` and `onFiltersChange` (which defaults to applying the filters at once), plus `App.setFilters`.
  - **`layout()`:** it runs `applyQuiet` on every card, filters with `matches`, and only rebuilds the grid when the visible elements change.
  - **The count:** "N changes", or "V of N changes" with a title of "K hidden by the filters".
  - **The empty states:** the getting-started page only shows with no cards *and* no filters. Otherwise a filtered view with no matches shows `.no-match`, "No changes match these filters", with a Clear button.
  - **Ticks and filter changes:** `updateTimes()` now runs `layout()`, so a status filter follows the clock. Both it and `setFilters` wait for a successful load (`loaded`), so a load error isn't wiped.
- **`views/cards.ts`:** it returns a `ViewHandle`, whose `update(params)` runs `app.setFilters(parseFilters(params))`. A filter choice calls `navigate("/?" + toQuery(filters))`, or `/` when there are none.
- **`types.ts`:** `CardAgent.memberId`.
- **Tests:**
  - `filters.test.ts`: parse, write, match, choices and options;
  - `app.test.ts`: the "mountApp filters" scenarios, plus the load error kept and the dropped-filter note;
  - `views/cards.test.ts`: address order with no remount, refetch or reconnect; Back; a shared link; Clear all; and "All …" removing a key.
