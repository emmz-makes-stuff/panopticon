# Section 4 done: personal tags in reports

<!-- Section: 4 · Tasks: 4.1 · Base: 92e5231 -->

**The contract:** `ReportProgressArguments.PersonalTags` (`IReadOnlyList<string>?`, wire name `personalTags`).
`ToToolArguments` sends it only when it isn't null, and an empty list goes out as `[]`, because that clears.

**The tool:** `ReportProgressTool` has a `personalTags` parameter. `Validate` parses it with
`TagText.TryParseAll(…, MaxPersonalTags)`, and a failure throws `McpException("Personal tags: <error>")` before
anything is stored or recorded. The result goes in `ReportInput.PersonalTags` (`IReadOnlyList<Tag>?`).

**The recorder:** `ReportRecorder` decides `latestForAgent` before it updates `ChangeAgent.LastReportedAt`: either the
`ChangeAgent` is new, or `receivedAt >=` its previous time.
- **When it is:** with tags in the report, it deletes that `(change, agent)`'s `change_agent_tags` rows and adds the
  new set through `changeAgent.Tags`, so EF inserts the `change_agents` row first.
- **When it isn't:** an older report committing last leaves the tags alone.
- **Freezing needs nothing extra:** the `AlreadyArchived` early return records nothing, and that's what freezes the
  tags.
- **Linking:** it moves the change in place, so the tags come along (tested).
