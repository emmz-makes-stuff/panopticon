**The parser:** `src/Panopticon.Contracts/Tags.cs` (design D1).
- **`Tag(Key, Value?)`:** a record whose equality uses `KeyKey`/`ValueKey`, the lower-cased forms (`ValueKey` is `""`
  for a bare key). `Text` gives the canonical `key` or `key: value`.
- **`TagText.TryParse`:** trims the text, splits at the first `:`, then trims each part. Keys are ASCII letters,
  digits, `-`, `_` and `.`. Each part is 1 to 40 characters, and a value can't contain `\r` or `\n`. Errors start
  with the quoted tag, e.g. `"has space": a key can only have letters, digits, '-', '_' and '.'.`
- **`TagText.TryParseAll(texts, max, …)`:** collapses duplicates (the first casing wins) and refuses more than `max`.
- **The limits:** `MaxPartLength` 40, `MaxPersonalTags` 20, `MaxProjectTags` 200 and `MaxFilterTags` 20.
- **No regex:** the key rule is a char check, so there's no `[GeneratedRegex]`, contrary to what D1 says. Simpler,
  and AOT-safe either way.

**The data model:** in `Entities.cs` and `PanopticonDb.cs` (D2), with migration `20261110153322_Tags`.
- **`ProjectTag`:** unique on `(project_id, key_key, value_key)`, and cascades when its Project is deleted.
- **`ChangeProjectTag`:** keyed `(change_id, tag_id)`. It cascades from both the change and the tag, and has an index
  on `tag_id`. The navigation is `Change.ProjectTags`.
- **`ChangeAgentTag`:** keyed `(change_id, agent_id, key_key, value_key)`. It hangs off `ChangeAgent` (`ChangeAgent.Tags`)
  with a cascade on the composite FK, and has an index on `(key_key, value_key)`.
- **Linking needs no tag code:** `ReportRecorder.FindOrAddChangeAsync` moves a personal change by setting its
  `ProjectId` in place, so its `change_agents` rows, and their tags, keep their `change_id`. A retired copy keeps its
  own frozen rows.
