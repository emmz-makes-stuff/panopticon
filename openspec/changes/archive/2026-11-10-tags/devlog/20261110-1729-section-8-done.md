## 8.4, tags live

- **`live.ts`:**
  - `PROJECT_TAGS_CHANGED`, the `ProjectTagsChange` type, and `parseProjectTagsChange`. It is strict: a tag
    without a string `id` and `key` makes the whole event null. A missing `value` reads as a bare key.
  - `retagCard(card, change)` returns the same card when it isn't in that Project or nothing changed. Otherwise it
    rebuilds `projectTags` by filtering the event's list to the ids the card has. The server sends the list
    ordered by `KeyKey`, then `ValueKey`, so a rename that changes the order comes out in the right order with no
    sort on the client. Project ids compare case-insensitively.
- **The dashboard:** `App.retagProject(change)` re-renders the changed cards in place. A retag isn't a report, so the
  card keeps its place and its `updated` mark, with no lighting. `layout()` reruns `matches`, so a card that §9's tag
  filter no longer matches will go out with no extra work.
- **The change page:**
  - `tagPicker` gains `projectTagsChanged(change)`. It retags the picker's own card, then refetches
    `GET /api/projects/{id}` so that an open panel lists an added or renamed tag.
  - The page also retags its `latest` copy, without re-rendering the header.
  - **Why the picker owns this:** after a toggle, the picker's card (from the POST answer) is newer than the page's
    `latest` until the `change-updated` refresh lands. Re-rendering the header from `latest` would briefly undo
    the toggle. A test covers this race.
- **`change-updated`:** this needed nothing new. Cards already carry their tags per viewer, and `upsert` and the
  change-page refresh re-render from them.
- **Tests:**
  - `live.test.ts`: rename and reorder, delete, an add that is a no-op, keeping the `updated` mark and the place,
    malformed events, and `parseProjectTagsChange` units.
  - `tagPicker.test.ts`: a rename shown in the chips and in an open panel, with no page refetch and other Projects
    ignored, plus the toggle race.
- **Limit:** the task's "filtered dashboard drops the card" check waits for §9, which brings the tag filter. For now
  the tests check that the chips update.
