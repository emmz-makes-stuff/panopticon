# Section 4 done: README front page and the docs split

<!-- Section: 4 · Tasks: 4.1–4.4 · Base: 73955c0 -->

The README is now a 63-line front page: tagline, the problem, six "what you get" bullets, how it works, getting on a
server (by invitation, or run your own), documentation links, contributing, and the licence. The old manual moved to
`docs/using.md`, `docs/development.md` and `docs/self-hosting.md`.

**4.1, wording kept.** `using.md` and `development.md` were cut from the old README by line range, so their text is
the old text. The check: of the old README's 275 non-blank lines, 213 appear verbatim in the new files. Each of the
other 62 falls under one of these deliberate edits:

- the old intro paragraph and link list, replaced by the new front page;
- `###` → `##` headings;
- relative links rewritten for `docs/` (`cli.md`, `dependencies.md`, `../src/…`, `../.railway/…`, `../.github/…`);
- the configuration table, which gained a Required column;
- the two "After deploying this version" back-fill notes, moved to self-hosting's Upgrading section as "the version
  that added the history / the metrics";
- the seams: "sign in (below)" and "builds this image" in `development.md`, the container section's intro, and the
  `CLAUDE.md` line, which now also points at `CONTRIBUTING.md` and `AGENTS.md`;
- `panopticon login --server http://localhost:7480` in the user guide, now `https://panopticon.example.com`, with a
  line giving the local address.

`development.md` also gained one sentence after "Run it locally" pointing at `make install`, because a local server
has no CLI builds.

**4.2: `docs/self-hosting.md`, checked against the code.** Every config key the server reads (`ConfigKey`/`Section`
constants plus `ConnectionStrings:Panopticon`) is in the table. Two were undocumented before:

- `Panopticon:Prompts:*` (four timings), with defaults from `PromptOptions`;
- `Panopticon:CliDirectory` and `Dashboard:KeepAlive` (default 25s, must be positive). The old README listed neither.

"Required" follows the `ValidateOnStart` rules in `ServerSetup.cs` (PublicUrl, the Resend key, and From when a key is
set, outside Development) and `S3Options.Validate` (Bucket, AccessKey, SecretKey). New facts, each checked:

- **Proxies.** `AuthLimits.ClientKey` uses `RemoteIpAddress`, and there's no forwarded-headers middleware. Behind a
  proxy, the per-address limits (20 link requests and 10 device starts an hour) are shared by every client.
- **CLI versions.** `make cli-dist-linux` stamps `CLI_DIST_VERSION`, which defaults to `0.0.0-dev`, so the guide says
  to pass the tag's version.
- **Releases.** Release asset names (`panopticon-<platform>[.exe]` plus `SHA256SUMS`) are from `deploy.yml`, and the
  `cli-dist/` layout is from `stage-deploy-context.sh`.
- **Image environment.** The `Dockerfile` sets no `ASPNETCORE_ENVIRONMENT`, so the container runs as Production.
