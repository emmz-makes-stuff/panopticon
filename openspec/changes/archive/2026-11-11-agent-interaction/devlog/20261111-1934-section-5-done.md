# §5 done: `panopticon hook`, `panopticon away` and the link file

<!-- Section: 5 · Tasks: 5.1–5.5 ticked · Base: ff916bc -->

The CLI side of the change is built: the bridge records each working tree's change, `panopticon hook` sends session
events and handles prompts, and `panopticon away` sets the switch.

**What was built:**

- **5.1, the link file:**
  - `Config/WorktreeLinksFile.cs` reads and writes `worktrees.json` next to the config, as
    `{<worktree root>: {change, at}}`. The key is the root from `git rev-parse --show-toplevel`, so on macOS it's the
    `/private/var` path.
  - `Config/UserOnlyFile.cs` is the atomic 0600 write, pulled out of `CliConfigFile.Write`, which now uses it too.
  - `ProgressReporter.LinkWorktree` runs only after the server accepts a report. An archived report calls `Clear`,
    which removes the entry only while it still names that change.
  - IO and permission failures are logged and never fail the report.
  - A file that can't be read counts as empty: it's a cache.
- **5.2, activity and the change:**
  - `Hook/ActivitySummary.cs` follows D2. The input fields it reads: `file_path`, `notebook_path`, `description`
    (Bash, Agent, Task) and `skill`.
    - **Fallbacks I chose, which the spec doesn't set:** "Editing a file", "Running an agent" and "Using a skill".
    - It collapses whitespace and cuts on whole text elements. `MaxLength` comes from `SessionLimits`.
  - `Hook/SessionChange.cs` resolves the change from the link, then a `change/<name>` branch
    (`GitRepository.GetBranchAsync`), then null. Both names must pass `ChangeDocuments.IsPlainName`, pulled out of
    `ResolveChangeDirectory`.
- **5.3, the async events:**
  - `Hook/HookCommand.cs`: `HookEvent.Parse` reads the event, and `StateFor` maps it to a state.
  - `PostToolUse` on `AskUserQuestion` sends working with no activity.
  - There's a 4s budget for everything but a held prompt's wait.
  - Failures go to `Hook/HookLog.cs` (`hook.log`, moved aside to `.1` at 1 MB). The hook writes nothing to stdout
    or stderr, and saved-config problems go to the log too.
  - `Hook/AgentApiClient.cs` is a REST client that sends `X-Panopticon-Request: 1` on every request but a GET, and
    maps status codes to its own `BridgeException` messages.
    - **Not shared with `ServerForwarder`, as D3 suggested:** the forwarder's mapping is built around MCP client
      exceptions.
    - `BridgeException` gained `StatusCode`.
  - `BridgeSettings.RequireApi()` gives the base URL: `RequireServer`'s, without `mcp`.
  - Paths are in `Contracts/AgentSessions.cs` as `AgentApiPaths`, and the server's constants now use them.
- **5.4, prompts:**
  - `PromptKindFor`: `PreToolUse` on `AskUserQuestion` is a question. `PermissionRequest` on anything else is a
    permission. A `PermissionRequest` on `AskUserQuestion` is ignored.
  - `Hook/PromptHookOutput.cs` parses the questions, builds the permission preview and writes D7's output.
    - **Preview format, my call:** Bash's `command`, or any other tool's input as indented JSON, cut to 2 KB.
    - **`updatedInput`:** the original input with `answers` added, as §1 confirmed.
    - **A deny with no message:** "Denied by X via Panopticon.".
  - A question that can't be read or breaks the limits isn't posted. The hook sends a waiting session event instead,
    so the card shows it, and logs why.
  - A preview that fails to upload is logged, and the hook keeps waiting: the dashboard can still deny.
  - `PromptWaitOptions`: 8h hold, 60s server loss, 2s retry, and a 30s per-call timeout.
    - **The timeout changed from 40s in self-review:** two hung calls then use up the 60s, so the terminal takes
      over in about a minute.
- **5.5:** `Hook/AwayCommand.cs`; `panopticon away` with no argument prints the state, and with `on` or `off` sets
  it. Usage errors and failures exit 1 on stderr, like `tags`. `docs/cli.md` has a new section, "Session activity and
  away mode", plus the `worktrees.json` and `hook.log` notes under Configuration and a troubleshooting entry.
  - **Docs ahead of the code:** the new section mentions the dashboard header's away switch, which §6 builds.

**Gotchas:**

- On a server started with `UseKestrel`, use `SeedApiTokenAsync`, not `MemberTokenAsync`: the latter signs in
  through the in-memory client, which gets "Connection refused (localhost:443)".
- For the in-process prompt tests, use `Factory.Server.CreateHandler()` with base `http://localhost/`.
- The published-binary tests need `make aot` first (`make test` does it).
