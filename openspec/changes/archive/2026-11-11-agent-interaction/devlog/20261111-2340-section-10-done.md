# Section 10 done: races in sessions, prompts and the live stream

- **10.1 Ordering (F2).**
  - `SessionEventRequest.OccurredAt` is optional. `HookCommand` stamps it with `clock.GetUtcNow()` when `RunAsync`
    starts: one run per hook process, and testable.
  - `PresenceStore.Record` and the new `End` keep the newest stamp on `Entry.OccurredAt`.
  - An event strictly older than that stamp is ignored. A stamped `SessionEnd` leaves a tombstone in `_ended`, and an
    event no newer than the end is ignored too.
  - A newer event (a resumed session) clears the tombstone. `Sweep` prunes tombstones after `StaleAfter`.
  - Unstamped events (an older CLI) apply as before and don't move the stamp. `Ask` carries the stamp forward.
  - The endpoint calls `End` for `Ended`. `Remove` is still the sweep's path, with no tombstone.
- **10.2 Answers never lost (F3, F4).**
  - `DropPrompt` keeps an answered prompt no wait has read yet, marked `Detached`. `WaitAsync` reading a settled prompt
    marks it `Read`, and removes a detached one. `Sweep` drops detached ones `WaitGrace` after `AnsweredAt`.
  - `DELETE /api/agent/prompts/{id}` calls `PresenceStore.Release`: 204 for a known prompt (it releases one that's
    pending and unclaimed), 404 for an unknown one or another member's. A claimed prompt is left to land, the same
    trade-off as F5.
  - The hook wraps the preview step. On any exception it releases with its own 2s timeout (`ReleaseTimeout`), because
    the budget is already spent, then rethrows.
  - The CLI test hangs only the preview (`StubServer.HangWhen`) until the 4s budget runs out, so it takes about 4s.
- **10.3 Resync (F8).**
  - `ChangeBroadcaster.Subscribe` uses the `itemDropped` overload to set a per-subscription flag (`Drops`).
  - `StreamAsync` checks `TakeDropped()` before each event it reads, not once per wake. Otherwise a drop while it's
    suspended at a `yield` waits for the next event.
  - On `resync`, `connectLive` calls `app.refresh()` (on failure: offline and reconnect, as `projects-changed` does)
    and `onCatchUp`. The change page calls `refresh()` and `env.refreshAway()`.
  - New: a reconnect after the first open also calls `onCatchUp` / `refreshAway`. Before this, the away switch
    loaded only at sign-in, so a reconnect could miss `away-changed` too.
- `design.md` D3 has the new endpoint, `occurredAt` and `resync`.
