- **Fields:** every event has `session_id`, `cwd` and `hook_event_name`. Tool events have `tool_name`,

  `SessionEnd` has `reason: "prompt_input_exit"`. `PermissionRequest` has `tool_name`, `tool_input` and
  `permission_suggestions`, but no `tool_use_id`.
- **D7, answering a question: works.** A sync `PreToolUse` hook returned `permissionDecision: "allow"` with
  `updatedInput` = the original input plus `answers`, and `additionalContext`. The agent got
  `{"[auto] Pick one":"Red","[auto] Pick some":"Hooks, Web"}` and the context, and the terminal asked nothing. The
  terminal's own multiple-choice answers use the same `", "` join (`"Web, CLI"`).
- **D7, permissions: work.** `decision.behavior: "allow"` ran the tool once and saved no rule
  (`.claude/settings.local.json` has no `permissions`). `"deny"` with a message gave the agent "Error: Denied by Spike
  via Panopticon: …".
- **D6, holding: 900s survived** with `timeout: 30000` (started 16:32:41Z, finished 16:47:41Z). The full 8 hours
  wasn't tested; that's left as an open question in the design.

**Found, and folded into the spec, design and tasks:**

1. An `AskUserQuestion` that the `PreToolUse` hook doesn't answer also raises a `PermissionRequest`, at the same
   moment. The permission hook must ignore it, or every question would be posted twice. This went into:
   - `agent-presence` "Session states", with the new scenario "A question is not a permission prompt";
   - D1's table and its new "Found in §1" notes;
   - task 5.4.
2. A denied tool gets no `PostToolUse`. So when the server records a web answer, it sets the session back to working
   itself (D6, task 4.4). A deny in the terminal is cleared by the next `PreToolUse`, `Stop` or `UserPromptSubmit`.
3. Sandbox-auto-approved Bash raises no `PermissionRequest` at all, so it never reaches the dashboard. In the first
   run this made the Bash allow and deny tests a no-op; the second run used Write and Edit instead.

- My expectation for run 2's step 3 was wrong, not the hook: it matched on the file name, so it allowed again.
- The agent in run 1 claimed step 9 "returned straight away". Emmz corrected it: it held for 15 minutes, and the log
  agrees.
