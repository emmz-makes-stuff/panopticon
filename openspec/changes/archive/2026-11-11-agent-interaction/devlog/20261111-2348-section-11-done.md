The second `/code-review` (medium, `4b7b371..HEAD`) gave 10 candidates. I checked each against the code. Emmz chose all
four groups, which became §11 and §12. I judged #7 (`upsert` dropping a report's sessions) not real:

- a reconnect's `render` takes the server's sessions;
- a card hidden by a filter still gets `session-updated`.

- **11.1 (#1, #9).**
  - `Find` returned `_sessions[prompt.Session]`, which threw for a detached prompt whose session had ended. 10.2
    introduced that, and it gave a 500. It now gives null, so the answer endpoint returns 404, as before 10.2.
  - `Newest()` is gone: once `IsStale` has passed, `occurredAt ?? existing` is the same.
- **11.2 (#2).** `PromptRequest.OccurredAt`, which the hook stamps from `_startedAt`.
  - **A deliberate difference from the task's wording:** `Ask` never ignores a prompt as stale. A prompt comes from a
    sync hook, so the terminal really is waiting on it. `Ask` moves the stamp forward (never back) and clears an end
    tombstone, so a late, older event can't clear the prompt.
- **11.3 (#3, #10).**
  - The preview upload and `WaitAsync` share one `try`, and any exception releases the prompt, then rethrows.
    `ReleaseAsync` now has its own `CancellationTokenSource(ReleaseTimeout, clock)`, not linked to the run's token,
    since that token may be the one cancelled.
  - The wait's own exits release nothing: at the hold limit the server releases the prompt itself, and after a lost
    server it can't be told.
  - The preview step is a helper, `SendPreviewAsync`.
- **11.4 (#6).** `PromptOptions.LateEventWindow` is 1 minute, and validated at start-up.
  - `IsStale` checks the window itself, so it doesn't depend on the 15s sweep cadence. `Sweep` prunes tombstones by
    the window.
