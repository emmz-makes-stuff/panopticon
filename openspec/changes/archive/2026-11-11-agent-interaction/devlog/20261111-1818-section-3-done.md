**Built together.** `DashboardEndpoints.StreamAsync` throws `UnreachableException` on an event type it doesn't
know, so the store couldn't publish until the stream handled the new events. 3.1 and 3.2 were built in one go and
tested separately.

**3.1, `src/Panopticon.Server/Presence/PresenceStore.cs`:**
- `PresenceStore` (singleton) keys sessions by `(memberId, sessionId)`. A session with no active card is kept with
  a null placement: it shows nowhere, and its `SessionEnd` still removes it.
- It publishes `SessionUpdated` / `SessionEnded` itself, under its own lock, so one session's events go out in
  order. The broadcaster's lock is only ever taken inside the store's, never the other way round.
- **Moving to another change** publishes `SessionEnded` on the old one first.
- **`Since`** restarts when the state or activity changes. A repeat of the same activity keeps it.
- **Activity** is kept only while working.
- **Order:** oldest first, by an insertion counter. Two sessions first seen in the same instant had tie-broken on a
  random v7 Guid, which flaked a test.
- **`SessionView.Id`** is a server-made Guid. Claude Code's `session_id` never leaves the server.
- **`PresenceSweep`** (hosted) calls `Sweep()` every minute, expiring sessions whose last event is at least
  `StaleAfter` old.
- 8 unit tests: `tests/Panopticon.Server.Tests/Presence/PresenceStoreTests.cs`.

**3.2, `Presence/AgentSessionEndpoints.cs`:**
- `POST /api/agent/sessions/events` is on the `Reporter` policy, and the member comes from the token.
- **400s:** missing repo, change, session id (max 200) or machine (max 100); activity over 120 characters or with a
  control character; an unknown state (from the contract).
- **No member:** a bootstrap token's events get a 204 and are dropped. There's no member to own the session.
- **`SessionChanges.FindAsync`** matches like a report: the Project scope when the member belongs to it, else
  personal. A Project that isn't theirs, or isn't a Guid, gives no card, not an error.
- **Card reads:** `ChangeCard` gains `Sessions` (init) and a computed `LastActiveAt`; the order is still by
  `LastReportedAt`. `ChangeCards(PanopticonDb db, PresenceStore? presence = null)` stays optional, so the
  integration tests' `new ChangeCards(db)` keeps working. `ListAsync`, `GetAsync`, `GetIncludingArchivedAsync` and
  the change page add sessions; history doesn't.
- **SSE:** `session-updated` sends `{changeId, session}` and `session-ended` sends `{changeId, sessionId}`. Each is
  filtered by `Viewer.CanSee(scope)`, like cards.
- **Gotcha:** every non-GET `/api` request needs `X-Panopticon-Request: 1` (`RequestHeaderMiddleware`), or it gets
  a 403. The hook's `AgentApiClient` (5.3) must send it, as device login does.
- 10 endpoint tests: `Presence/AgentSessionEndpointTests.cs`. Test helpers: `TagWorld.CreateAsync` takes an
  optional clock; `Infrastructure/SseReading.cs` reads streams. The default member's display name is "member".

**Emmz's decision: a held prompt pins its session.** A side agent noticed that a held prompt can wait 8 hours
(D6), but a session expires after 4 quiet hours, and a paused session sends no events. Emmz chose "held prompt
pins it" over "wait polls count as events" (which would keep moving `LastActiveAt`) and "cap holds at the
threshold". The decision is recorded in:
- `agent-presence`: new requirement "A held prompt keeps its session", with scenarios "Away overnight" and
  "Released, then quiet". "Presence is not history" points to it.
- D4: the sweep skips a session holding a prompt.
- Task 4.3: implement it and test "Away overnight". **Implementation:** `Sweep()` must skip entries with a held
  prompt. On answer or release, the stale threshold counts from that moment, so set the entry's last-event time
  then.
