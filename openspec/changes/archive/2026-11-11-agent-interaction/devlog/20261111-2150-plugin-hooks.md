**Emmz's answers (2026-11-11):**

- The plugin repo works on a `change/agent-interaction` branch, not `main`. That keeps `main` from pointing at hooks
  that need a CLI not yet released (design, Migration Plan).
- The wrapper's test is a plain bash script in that repo, so no new tool is needed.

  version stays 0.1.0.

**Built:** commit `e54b620` in `../panopticon-skills`, on `change/agent-interaction`.

- `plugins/panopticon/hooks/panopticon-hook.sh`:
  - With no `panopticon` on `PATH`, it drains stdin and exits 0.
  - Otherwise it runs `panopticon hook` and passes stdout on only when the CLI succeeds.
  - stderr is dropped, and it always exits 0.
- `hooks.json` has D1's table, beside the existing `tasks-changed.sh` entry:
  - async with `timeout: 10`: `PreToolUse` on everything but `AskUserQuestion`, `PostToolUse`, `Stop`,
    `UserPromptSubmit` and `SessionEnd`;
  - sync with `timeout: 30000`: `PreToolUse` on `AskUserQuestion`, and `PermissionRequest` on everything but
    `AskUserQuestion`.
- `plugins/panopticon/tests/panopticon-hook.test.sh` tests 4 cases: no CLI; a CLI that answers (its stdout passes
  through, with the event it read on stdin); a quiet CLI; and a CLI that fails after printing (nothing passes
  through).

**Decision: the "all but `AskUserQuestion`" matcher is `^(?!AskUserQuestion$)`.**

- The hooks docs (code.claude.com/docs/en/hooks) say a matcher with any character other than letters, digits,
  `_ - , |` and spaces is a JavaScript `RegExp`, tested unanchored.
- I checked the pattern in node: `Bash`, `Write` and `AskUserQuestions` match, and `AskUserQuestion` doesn't.
- **This matters.** The CLI treats every `PreToolUse` on `AskUserQuestion` as a question. If the async entry
  matched it, every question would be posted twice, once by an async hook that can't return the answer.
- The §1 spike used no matchers, so **8.2 must confirm this on a real Claude Code**. One question should appear on
  the card, not two.
