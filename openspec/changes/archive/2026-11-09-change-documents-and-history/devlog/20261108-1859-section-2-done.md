What landed:
- **Shared limits.** `Panopticon.Contracts.DocumentLimits` holds the limits and the extension list, so the
  bridge (§4) and the server read the same numbers:
  - `MaxTasksBytes` 1 MiB, `MaxDocumentBytes` 262,144 and `MaxTotalBytes` 4,194,304, all binary, as Emmz chose
    in the §1 note.
  - The extensions are `.md`, `.yaml` and `.yml`, compared without regard to case.
- **2.1:** `Reporting/DocumentChecks` runs from `ReportProgressTool.Validate`, which takes new `documents` and
  `archive` tool parameters. `ReportInput` gains init-only `Documents` and `Archive`.
  - Path checks: empty, longer than 512 characters, a `\`, rooted (a leading `/`, `Path.IsPathRooted`, or any
    `:`, which catches drive paths), an empty, `.` or `..` segment, or a control character. Then the extension.
  - Duplicates are compared ordinally.
  - `tasks.md` in `documents` must equal `tasksMarkdown`.
  - If the documents leave out `tasks.md`, the server adds it, so every manifest holds the tasks.
  - **Addition beyond D6:** `archive` must match `^\d{4}-\d{2}-\d{2}-<change>$`, with the change compared without
    regard to case. The server stores that name, and D3 defines its shape, so the trust boundary checks it.
- **2.2:** each document is stored content-addressed (`tasks.md` reuses its hash, so it isn't stored twice).
  - Each event gets `report_documents` rows. They need the event's database id, so there's a second
    `SaveChanges` in the same transaction.
  - `change_documents` is replaced whole only when `receivedAt >= LastReportedAt`, through `ExecuteDeleteAsync`
    and then inserts.
  - An ordinary report still returns its own computed snapshot, as before.
- **2.3:**
  - **The repeat check comes first:** `(repo, archive_folder)` is looked up before anything else, and if it
    exists, the result is `ArchiveOutcome.AlreadyArchived`, with no writes and no event.
  - **Active changes only:** the `FOR UPDATE` lookup now filters `archived_at IS NULL`.
  - **Archive time:** the archive gets `receivedAt`.
  - **Concurrency:** concurrent archived reports race on the partial unique index and retry, so they end in one
    `Archived` result.
- **2.4:** `ChangeEvent` is a closed union, `Updated(card)` or `Archived(id)`.
  - `PublishArchived` sends `Archived`, and the SSE stream writes `change-archived` with `{"changeId": …}` and
    no event id.
  - The tool publishes the archived event only for `Archived`, and nothing for `AlreadyArchived`.
  - `ChangeCards.ListAsync` filters out archived changes. `GetAsync` doesn't, because only ordinary reports use
    it.

**Test-infrastructure fix (S3Fixture).** The full server suite started failing intermittently, 4 of 6 runs, with
SeaweedFS "We encountered an internal error" on `PutObject`. The cause is volume exhaustion:
- The OrbStack Docker disk is 93% full, with 18 GB free.
- `-volume.max=0` sizes the volume limit as free disk / volume size, so about 280 volumes at 64 MB each.
- Single-copy collections grow 7 volumes at a time, and every test bucket is a collection.
- §2's extra writing tests pushed the suite past the limit.

The fixture now uses `-master.volumeSizeLimitMB=8` and `WEED_MASTER_VOLUME_GROWTH_COPY_1=1`. After the fix, the
full suite passed 4 runs out of 4. I haven't checked which of the two settings does the work; the smaller volumes
alone raise the limit about 8×. **Tell Emmz that the OrbStack disk is at 93%.**
