# Section 8 done: review fixes, the bridge's archive reports

<!-- Section: 8 · Tasks: 8.1–8.2 · Base: ecfc223 -->

- **8.1:** `ArchiveWatcher` now retries.
  - **How:** `ScanAsync` returns whether every archived report went through. While one is pending,
    `NextScanAsync` waits for a folder event *or* `BridgeSettings.ArchiveRetryInterval`, a new init-only property
    defaulting to 30 s, and then rescans. It logs "Will retry the archived report in {Seconds} s".
  - **Test:** `ArchiveWatcherTests.Server_down_at_archive_time_is_retried_by_the_watcher_itself`, with a 1 s
    interval and no tool call after the archive.
  - **Docs:** `docs/cli.md` § Archives covers the retry and one-report-at-a-time.
- **8.2:** `ReportProgressResult` gained an optional `Archived` (the folder name).
  - **Who sets it:** only the bridge, with `result with { Archived = archive }` in `ProgressReporter`. The server
    leaves it null, and null fields aren't written, so the server's reply on the wire is unchanged.
  - **Reply text:** `Describe()` appends " · archived as <folder>", and the structured content carries `archived`.
  - **Tests:** `BridgeDocumentTests` asserts the exact text and field. The e2e gained step 7: report again after
    the archive and get "… · archived as 2026-11-08-team-auth-e2e".
  - **Docs:** `docs/cli.md` gives an example of the reply.
