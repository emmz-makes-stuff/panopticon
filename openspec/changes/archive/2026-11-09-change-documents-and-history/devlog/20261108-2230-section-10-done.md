# Section 10 done: review fixes, web navigation

<!-- Section: 10 · Tasks: 10.1–10.2 · Base: 86e2516 -->

- **10.1, the router:** a view may now return a `ViewHandle` (`{ teardown, update? }`) as well as a bare teardown.
  - **The router keeps `shown`:** the path, the query, the view and its `update`.
  - **Same path, same view, other query:** the router calls `update(params)` instead of tearing down and rebuilding.
  - **A popstate with the path and query as shown** (a hash-only jump, e.g. a footnote anchor) is ignored.
  - **Teardown order:** the old view is now torn down after the guard and the match, not before. No view relied on
    the old order.
- **10.1, `views/change.ts`:** it returns `{ teardown, update }`.
  - **`update`** sets `requested` from the new `?doc=` and re-shows from `latest` (the last `ChangePage`). There's
    no header fetch and no new stream.
  - **Refresh ticket:** live refreshes now have their own `refreshing` ticket, so picking a document mid-refresh
    doesn't drop the refreshed header. A refresh after leaving the page is ignored, because teardown now clears
    `closeStream`.
  - **Tests:** two router tests (a hash-only popstate does nothing; an in-place update, then a teardown on another
    path) and a change-view test (switching documents makes one `GET /api/changes/c1`, keeps one open
    EventSource, and keeps the same header node).
- **10.2:** a failed first history load turns "Show more" into "Try again". A success turns it back. Test:
  `history.test.ts` "a failed first load offers to try again, which loads the page".

  `prettier --write`, then a full rerun.
