Emmz's answers at the start of the session:
- **Size limits are binary.** 256 KB means 262,144 bytes and 4 MB means 4,194,304 bytes, the same units as the
  existing `tasks.md` limit of 1 MiB (`TasksParser.MaxBytes`). Error messages say "256 KB" and "4 MB", as the
  spec words them.
- **Pace.** Run the section loop through §4, then stop before §5 (the web views and the `frontend-design` pass)
  so Emmz can look.

What landed:
- **1.1:** a `ChangeDocument(Path, Content)` record, and optional `Documents` and `Archive` fields on
  `ReportProgressArguments`, with the wire names `documents` and `archive`. `ToToolArguments` adds them only
  when they're set. `ContractsJsonContext` registers `ChangeDocument` and `IReadOnlyList<ChangeDocument>`.
  Tests check that a report without the new fields serializes byte-for-byte as before (exact JSON), and that one
  with them round-trips. Record equality doesn't compare lists, so the round-trip test compares `Documents`
  separately.
- **1.2:** migration `20261108184053_ChangeDocumentsAndHistory`:
  - `changes.archived_at` and `archive_folder`.
  - `ix_changes_repo_id_name_key` is now partial, `WHERE archived_at IS NULL`.
  - New `ix_changes_repo_id_archive_folder`, unique, `WHERE archive_folder IS NOT NULL`.
  - Two new tables, both with paths of at most 512 characters and `char(64)` hashes:
    - `report_documents`: primary key `(report_event_id, path)`, cascading from `report_events`.
    - `change_documents`: primary key `(change_id, path)`, cascading from `changes`.
- **Entity names:** the server entities are `ReportDocument` and `LatestDocument`, and the DbSets are
  `ReportDocuments` and `ChangeDocuments`. They aren't named `ChangeDocument`, which would clash with the
  contracts record wherever both namespaces are imported.

Self-review: no problems in §1 itself. One thing carries forward: `ReportRecorder.FindOrAddChangeAsync`'s
`FOR UPDATE` query doesn't filter on `archived_at IS NULL` yet. Nothing creates archived rows until §2.3, so
it's harmless for now, but 2.3 must add the filter, or `SingleOrDefault` will throw once a name has both an
archived and an active row.
