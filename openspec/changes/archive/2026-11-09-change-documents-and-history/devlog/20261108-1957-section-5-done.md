- **5.1:** new types in `types.ts` (`ChangePage`, `DocumentEntry`, `RenderedDocument`, `HistoryEntry`,

- **5.2:** the router supports `:name` segments.
  - **Matching** (`match()`): an exact path wins, then a pattern. Each named segment is URI-decoded, and an empty
    segment, one that won't decode, or one that decodes to a `/` doesn't match.
  - **`ViewContext.route`** carries the matched segments.
  - **`views/change.ts`:**
    - It loads the header first. A 404 shows "Change not found" with a link to `/`. A 401 returns quietly,
      because the shell is already sending the member to sign-in.
    - The document list is grouped (Change / Specs / Devlog / Other files) as `?doc=` route links, with
      `aria-current` on the shown one.
    - Without `?doc=`, it opens the proposal, else the tasks, else the first document. An unknown `?doc=` falls
      back to that and says so.
    - The document goes in with `innerHTML`, only from the documents endpoint, with a comment pointing at D8.
    - **Live:** only for an active change. It refetches on `change-updated` or `change-archived` for its own id,
      and on a reconnect. An archive shows a status line and closes the stream. A ticket counter drops stale
      fetches.
  - `links.ts` has `changeHref`, shared by the card, the change page and the history.
- **5.3:** `views/history.ts` lists rows linking to the change page, with "Show more" by `nextBefore` and an empty
