# §2 done: the Project page follows the stream

<!-- Section: 2 · Tasks: 2.1–2.2 · Base: 99dcfea -->

## What landed

- **`projectView`** (`web/src/views/projects.ts`) now holds `tags` (the `TagSection` from the last `render()`), `stream`,
  `left` and one `ticket` counter.
- **The stream:**
  - **Opening:** `follow()` opens `/api/events` through `env.createEventSource`, and only after the first `load()`
    rendered. `load()` now returns a boolean.
  - **`project-tags-changed`:** an event for this Project (ids compared without regard to case) calls
    `refreshTags()`.
  - **Reconnects:** an `onopen` after the first one calls `refreshTags()`. `onerror` does nothing, so the browser's own
    retry runs.
  - **Closing:** the view returns a teardown that sets `left` and closes the stream.
- **`refreshTags()`:**
  - **The fetch:** it takes a ticket and fetches `GET /api/projects/{id}`. It applies `tags.redraw(details)` only if
    its ticket is still the latest and the page hasn't been left.
  - **A 404** calls `notFound()`, which closes the stream and shows "There's no such Project".
  - **Any other failure** keeps the rows.
- **`load()`** also takes a ticket, so a full reload after the page's own write drops older live answers. Its 404
  path now goes through `notFound()` too, so it also stops the stream.

## Tests

`projects.test.ts`, `/projects/{id} live tags` (15 new). They cover:
- **Each spec scenario:** a rename, an add (with its count), a delete, another Project, the rest of the page staying
  put (typed invite and add-tag text survive, which closes §1's invite-form note), and "Missed while offline".
- **The edge cases:** a case-insensitive id, malformed events, an out-of-order pair of answers (a `hold()`/`release()`
  wrapper around the fake server), a failed refresh, a 404 on refresh, a first load that 404s, and leaving the page.
- **Reconnects:** the first open fetches nothing more, and a stream error does nothing.

I checked by mutation that the ticket, case-insensitivity and reconnect tests fail when their code is broken. **Gotcha:** `until()`
in `web/src/testing.ts` returns quietly when it runs out of turns. A test whose only check is an `until` passes even
when the condition never held. I found this in the case test and added an `expect` after it.
