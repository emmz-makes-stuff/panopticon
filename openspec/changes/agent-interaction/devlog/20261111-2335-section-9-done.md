- **9.1** `answerSummary` now reads as the spec words it: "Bob allowed Bash for Emmz", "Bob answered a question for
  Emmz". There's a new `web/src/answerList.test.ts` for every branch: allow, deny, no tool, and question.
  `views/change.test.ts` and `web/DESIGN.md` are updated.
- **9.2** `PresenceStore.WaitAsync` times out on the store's clock.
  - `ManualClock.WithTimers()` makes a clock whose timers fire only on `Advance`.
  - `ManualClock.StartingAt2026()` still uses real-time timers, so every existing host test behaves as before. Turning
    on manual timers everywhere would also gate `PresenceSweep`'s and `AuthCleanup`'s `PeriodicTimer`s on `Advance`.
  - The pending-after-timeout test moved from `AgentPromptEndpointTests` (a real 300ms) to `PresenceStoreTests` (the
    fake clock). There the timer is created synchronously inside `WaitAsync`, so advancing is deterministic.
    `PromptAnswerEndpointTests` and `AgentPromptEndpointTests` still cover a `Pending` reply over HTTP.
- **9.3** See `20261111-2320-9-3-body-drop-already-retried.md`. The test passed before the fix, because `HttpClient`
  buffers the body inside `SendAsync`. The `ReadAsync` wrap is defensive.
  - `StubServer.DropAfterHeaders` sends the headers, then a body that throws `IOException`.
- **9.4** `App.upsert` keeps a shown card's sessions, and takes a report's sessions only for a card new to the
  dashboard (`withSessionsOf`).
  - The "only its sessions moved" branch in `upsert` couldn't run any more, so it's gone. `render` (a refresh from
    `GET /api/changes`) is still the server's truth for sessions.
  - The new test fails against the old `app.ts`; I checked.
  - The change page wasn't affected: it refetches on `change-updated`.

**Gotcha:** run vitest from `web/` (`cd web && npx vitest run …`). `npm --prefix web exec -- vitest` runs from the
repo root, misses `web`'s config ("document is not defined"), and leaves a `node_modules/` cache at the root. I deleted
that cache.
