# §1 done: members and the data model

<!-- Section: 1 · Tasks: 1.1–1.4 done · Base: 61e3b40 (the proposal commit) -->

## Emmz's decisions for this change (2026-11-08, before the proposal)

- **Invites:** `Panopticon:InitialMembers` seeds the first members. After that, any member invites or removes
  members.
- **Tokens page:** each member manages only their own tokens.
- **Bootstrap token:** kept, but for Development only.
- **Dev email:** with no Resend key in Development, the sign-in link is logged instead of sent.
- **The card shows the member on each agent.**
- **Lifetimes:** links last 15 minutes, sessions 7 days (sliding), device codes 10 minutes. Tokens don't expire.
- The proposal was committed on its own (`61e3b40`), as walking-skeleton's was, so the tree was clean at the
  start.

## What landed

- **1.1** `Data/AuthEntities.cs` adds `Member`, `SignInLink`, `Session`, `DeviceLogin` and `ApiToken`. `Agent`
  gets `MemberId` and a `Member` navigation.
  - One migration, `20261108150815_TeamAuth`, adds them. The agents index becomes
    `(member_id, client_name_key, machine_name_key)` with `NullsDistinct: false`.
  - Secret hashes are `bytea` (`byte[]`).
  - **Deviation from D1:** `device_logins.user_code` is unique for all time, not just while pending. A partial
    index can't express "not expired", and 20⁸ codes is plenty. It's commented in `PanopticonDb`.
  - `PostgresFixture.CreateDatabaseAsync(string? targetMigration, ct)` is a new overload (CA1068 wants `ct`
    last). The upgrade test migrates to `Initial`, inserts an agent, then migrates to the latest.
- **1.2** `Auth/Secrets.cs`:
  - `NewSecret` (32 bytes, base64url, 43 characters) and `NewApiToken` (`pnp_` plus a secret);
  - `Hash` (SHA-256);
  - `NewUserCode`, `FormatUserCode` (`XXXX-XXXX`) and `NormalizeUserCode` (ignores case, `-` and spaces;
    null when it can't be a code).
- **1.3** `Auth/InitialMembers.cs` is an `IHostedService`, registered in `ServerSetup`.
  - It reads a list or one comma- or semicolon-separated value, so an environment variable works.
  - It fails on an invalid address, skips any existing row (removed ones included), and fails start-up if
    there's no active member.
  - `Auth/MemberEmail.cs` holds `Clean`, `Key`, `IsValid` (deliberately loose) and `DefaultDisplayName`.
    `MemberNames.Validate` (1–50 characters, trimmed) is in the same file, ready for §4.
- **1.4** `Panopticon:BootstrapToken` is optional, and outside Development it fails `ValidateOnStart`.
  - The new `Auth/PublicUrlOptions.cs` validates the URL shape only. Requiring it outside Development is
    task 2.1.
  - `appsettings.Development.json` sets `PublicUrl` to `http://localhost:7480` and `InitialMembers` to
    `dev@localhost.test`. It's a string, not an array, so a single `UseSetting` can override it.
  - The old "No token configured fails at start-up" test is now "starts normally" (Development and Testing).
    New tests cover the bootstrap token outside Development (Testing, Production) and an invalid `PublicUrl`.

## Gotchas and calls

- **`PanopticonFactory.Environment` defaults to `"Development"` for now.** The bootstrap token only works there,
  and most tests still report with it. **Task 6.3 must switch the default back to `Testing`**, once tests use
  per-user tokens.
  - The factory now also always seeds `PanopticonFactory.MemberEmail` (`member@example.com`) through
    `UseSetting(InitialMembers.ConfigKey, …)`. `Settings` can override it.
- **Under Development, static web assets serve the project's built `wwwroot`**, not `UseWebRoot`. So the 4
  app-shell tests use a `WebRootFactory(...)` helper in `DashboardEndpointTests`, with `Environment = "Testing"`
  and no bootstrap token.
- **The local container recipe** (`local/container.env`, README, the Dockerfile comment) no longer sets the
  bootstrap token: it would stop a Production container from starting. It sets `PublicUrl` and
  `InitialMembers` instead. Reporting from the container then has no working credential until §5–§7. **§2.1
  will also make a Production container need a Resend key.** Decide the container's email story in §2.1 or 9.1
  (a non-secret placeholder key won't send). I updated the README configuration table minimally. Its full
  rewrite is 9.2.
